# 后端与资源方案（2026-10-27）

> 针对「图片资源放哪里 + 后端怎么建」这两个问题，按当前项目实际情况给结论和可执行步骤。
> 后台代码已经在 `server/` 里跑通了，接口与小程序现有上报实现完全对齐。

---

## 一句话结论

- **图片**：跟着代码走的（图标、按钮、场景背景）**放分包里打包**，不要放服务器；会变的和用户产生的（运营图、训练录像）才放**对象存储 + CDN**。
- **后端**：先上 `server/` 这个零依赖 Node 服务（一台 1 核 1G 就够）；等要报表和多实例了再换 Postgres。不想碰服务器就选微信云开发。

## 一、图片资源放哪里

### 判断只需要三个问题

1. 这张图**会不会随运营改动**？会 → CDN/对象存储；不会 → 打包。
2. 这张图**首屏就要吗**？要 → 主包；只在某个游戏里用 → 该游戏的分包。
3. 这张图**多大**？单张 > 200KB 又想放主包 → 基本可以放弃，改分包或 CDN。

### 对照表

| 资源 | 放哪 | 为什么 |
| --- | --- | --- |
| 图标（tabBar、按钮、状态小图标） | `assets/icons/`（主包） | 首屏就用，几十 KB，省一次网络往返 |
| 游戏场景背景、立绘、贴图 | `pkgXxx/images/`（对应分包） | 不进主包，进游戏才下载，**离线可用** |
| 音轨 | `pkgRhythm/audio/rhythm/`（现状） | 同上，节奏训练已经这么放了 |
| 运营活动图、节日皮肤 | 对象存储 + CDN | 不发版就能换，包体永不增长 |
| 用户上传（头像、录像） | 对象存储（私有读 + 临时 URL） | 不能进包，且要权限控制 |
| 动画序列帧 | 分包 + 图集（或用 APNG/WebP） | 单张切图太多会撞分包 2MB 上限 |

### 本项目现在的体积余量

| 包 | 体积 | 上限 | 余量 |
| --- | --- | --- | --- |
| 主包 | 0.83 MB | 2 MB | **约 1.15 MB** |
| pkgRhythm | 0.49 MB | 2 MB | 约 1.5 MB |
| pkgFruit | 0.21 MB | 2 MB | 约 1.8 MB |
| pkgWire | 0.17 MB | 2 MB | 约 1.8 MB |
| pkgShoot | 0.04 MB | 2 MB | 约 1.9 MB |
| pkgRace | 0.10 MB | 2 MB | 约 1.9 MB |
| 全部 | 约 1.8 MB | 20 MB | 很充裕 |

**结论**：现在加几张背景图完全放得下，优先放分包，不要急着上 CDN。

### 如果要把节奏游戏的插画背景做成贴图

1. 尺寸：按 2 倍图做，`780×1688`（390×844 @2x），导出 **WebP 质量 80**，控制在 250KB 以内。
2. 位置：`pkgRhythm/images/scene-garden.webp`（放在游戏分包里，跟着分包一起下载）。
3. 体积核对：`pkgRhythm` 现在是 0.49MB，加一张 250KB 后仍在 0.75MB，安全。
4. 加载方式（Canvas 绘制）：
   ```js
   // renderer 里只加载一次，加载完成后画到离屏背景层
   const img = canvas.createImage()
   img.onload = () => { this.sceneImg = img; this.bg = null }  // bg=null 触发离屏重绘
   img.src = '/pkgRhythm/images/scene-garden.webp'
   ```
   注意：`createImage` 是异步的，**没加载完那一帧要回退到现在的程序化背景**，不要白屏。
5. 图片来源与授权要留痕：`pkgRhythm/games/rhythm/CREDITS.md` 写明作者 / 许可 / 链接。

### 什么时候必须要 CDN

- 图要**不发版就换**（运营活动、节日皮肤）
- 单图 > 500KB（比如整屏插画、视频封面）
- 图要给**小程序外的渠道**复用（H5、公众号文章）
- 团队多人协作，不想每换一张图就重新提审

### CDN 具体配置（以腾讯云 COS + CDN 为例）

1. 建存储桶（公有读、私有写），开 CDN 加速域名，例如 `img.example.com`。
2. 图片放 `img.example.com/rehab/rhythm/bg-v3.webp`，**文件名带版本号**，这样能设长缓存。
3. 缓存策略：`Cache-Control: public, max-age=31536000, immutable`（带版本号才敢这么设）。
4. 小程序侧：微信公众平台 → 开发管理 → 服务器域名 → **downloadFile 合法域名** 加 `https://img.example.com`。
5. 防盗链：CDN 开 Referer 白名单，允许 `https://servicewechat.com`。
6. 图片处理：用 CDN 的图片处理参数按需出图，例如 `?imageMogr2/format/webp/quality/80`，省一次手工压图。

> 域名必须 **HTTPS + 已备案**；小程序不接受 IP、不接受 http、不接受未备案域名。

## 二、后端怎么建

### 三条路，先选路线

| 方案 | 要不要备案 | 运维 | 成本 | 适合谁 |
| --- | --- | --- | --- | --- |
| **微信云开发（CloudBase）** | 不用（用微信给的域名） | 无 | 有免费额度，超出按量 | 不想碰服务器、只做小程序 |
| **自建 Node（本仓库已给）** | 要（域名 + HTTPS） | 自己维护，或交给 Docker | 1 核 1G 约 ¥60/月起 | 想完全掌控、后面要对接医院系统 |
| **云托管 CloudBase Run** | 用微信域名，免备案 | 无（托管容器） | 按量/包月 | 想自建代码但不想运维 |

**给你的建议**：先用 `server/`（已经写好、跑通、有测试），它只有一个文件依赖 Node 标准库；
等你有了备案域名，直接 Docker 上去就行。如果连服务器都不想买，就用微信云开发，
但那套是 `wx.cloud.callFunction` + 云数据库，和现在 `wx.request` 上报的实现要改一处适配层。

### 已经给你的东西

```
server/
├── index.js            HTTP 服务：鉴权、校验、幂等、静态文件
├── store.js            记录存储：原子写 + 串行锁 + 去重（换数据库只改这个文件）
├── README.md           接口文档 + 部署 + 安全清单
├── Dockerfile          一条命令出镜像
├── docker-compose.yml  带数据卷
└── static/             /static/** 的图片目录（CDN 之前先用它顶一下）
tools/server-smoke-test.js   18 项接口自检（已并入 npm test）
```

接口与小程序端 `utils/training-record.js` 的现有实现**逐字段对齐**：

- `POST /api/v1/records`，头 `Authorization: Bearer <TOKEN>`，2xx 即视为成功
- 同一 `recordId` 重复上报返回 `200 + duplicated:1`（小程序会自动重试 3 次，必须幂等）
- 参数错误 `400`、鉴权失败 `401`、请求体超限 `413`、服务端没配令牌 `503`

### 本地三步跑起来

```bash
export UPLOAD_TOKEN="$(openssl rand -hex 24)"   # Windows: $env:UPLOAD_TOKEN="..."
node server/index.js                            # 或 npm run server
curl http://127.0.0.1:8787/health               # {"ok":true,...}
```

### 小程序里要填的两处

1. 「训练设置 → 训练数据上报」：地址填 `https://api.example.com/api/v1/records`，令牌填同一个值。
   （四个游戏各有一份配置，都要填，或者你后续把这个配置提到全局。）
2. 微信公众平台 → 服务器域名 → **request 合法域名** 加 `https://api.example.com`。

开发和联调阶段：微信开发者工具 → 详情 → 本地设置 → 勾「不校验合法域名」，
可以先用 `http://127.0.0.1:8787` 或局域网 IP。

### 数据长什么样

一条记录就是一个扁平对象（节选真实字段）：

```json
{
  "recordId": "rhythm-1759...-a1b2",
  "gameId": "rhythm",
  "nickname": "体验用户",
  "songId": "slow_wave",
  "score": 2496,
  "rhythmAccuracy": 0.62,
  "directionAccuracy": 1,
  "overallHitRate": 0.85,
  "perfect": 12, "great": 8, "good": 3, "miss": 3,
  "comboMax": 18,
  "durationSec": 90,
  "leftHitCount": 15, "centerHitCount": 10, "rightHitCount": 8,
  "createdAt": 1759...,
  "receivedAt": 1759...
}
```

服务端会做的处理：白名单字段、字符串截断到 200 字、单条 > 8KB 拒绝、时间戳补全。
**不存**姓名、手机号、证件号；昵称是用户自填的显示名。

### 演进路线

| 阶段 | 数据量 | 方案 |
| --- | --- | --- |
| 现在 | 每天几十条 | JSON 文件（已给） |
| 3~6 个月 | 几万条，要按人/按周统计 | 换 Postgres：只改 `store.js` 的三个方法 |
| 有录像 / 大文件 | — | 文件走对象存储，库里只存 URL |
| 多实例 | — | 数据库 + 无状态服务，前面挂负载均衡 |

## 三、上线检查清单

- [ ] 域名已备案，HTTPS 证书有效（Caddy 自动续期）
- [ ] `UPLOAD_TOKEN` 至少 32 位随机串，不写进小程序代码，只填在治疗师设置页
- [ ] 服务器时间同步（`timedatectl`），否则记录时间会漂
- [ ] `DATA_DIR` 不在静态目录下，已做每日备份（`records.json` 拷到对象存储即可）
- [ ] 反向代理开 gzip、限流（防止被刷）
- [ ] 隐私政策写明：收集哪些字段、用途、保存期限、如何删除
- [ ] 「我的」页提供记录删除入口（现在是本地删除；接后端后要同时删服务端）
