## P0 · 上线前必须处理

### 1. 主包 90% 已用满，且没有分包
- **证据**：打包口径（去掉 tools/docs/源码目录与已 ignore 的 wav）约 **1.82 MB**；其中 `audio/` 804 KB、`games/` 426 KB、`pages/` 286 KB、`utils/` 205 KB、`race/` 78 KB。
- **风险**：再加一首曲子（约 120 KB）或几张图就会超 2 MB，上传直接失败；届时只能临时删功能。
- **建议**：现在就按游戏拆 4 个分包（`packageFruit` / `packageWire` / `packageRhythm` / `packageRace`），
  把 `games/*`、对应 `pages/*`、`audio/*` 放进分包；`utils/`、tabBar 三页、`components/` 留主包。
  预期主包降到 **600 KB 左右**，单个游戏分包 200~400 KB，后续加内容不再受限。

### 2. `race/` 只有构建产物，没有源码
- **证据**：`race/` 下只有 `engine.js`（77 KB 压缩后的 bundle）和 README；`pages/race/race.js` 直接 `require('../../race/engine.js')`。
- **风险**：赛车玩法出任何问题都改不动，只能整包替换。
- **建议**：把 `src/**`（26 个 ES Module）纳入仓库，并在 README 写清 esbuild 打包命令；或在下一个版本下线该游戏。

### 3. 文档与代码漂移
- `utils/rhythm-songs.js` 用的是 `.m4a`，但 `games/rhythm/README.md` 仍写「两首音轨是 22.05kHz WAV」——实际是**三首**且格式已换。
- 仓库里还留着 1.8 MB 的 `.wav` 源文件（已加入 `packOptions.ignore`，不进包，但占仓库、易误用）。
- **建议**：README 改成 m4a 与三首曲目；`gen_rhythm_audio.py` 的转换注释提升为一键脚本，wav 只作为中间产物不入库（或放 `.gitignore`）。

## P1 · 体验与稳定性

### 4. 音频播放器实例过多（可能静默失败）
- **证据**：`utils/game/audio.js` 的池——shooter 12 个 + BGM 1；casual 14 个 + BGM 1。节奏训练再加 `BeatClock` 1 个、`speaker.js` 2 个 → **单局 16~17 个 `InnerAudioContext`**。
- **风险**：旧基础库对 `createInnerAudioContext` 有数量上限（历史版本为 10），超了会创建失败且不报错，表现为「没声音」。
- **建议**：池上限压到 4（同类音效 2 个足够叠放），BGM 全应用共用 1 个；`speaker` 与 `AudioKit` 也共用一个池。

### 5. 字号偏小 + 对比度不足（康复/老年用户）
- **证据**：三个渲染器里 **81 处字号 < 10px**（最小 7.5px）。对比度实测：
  | 颜色 | 白底对比度 | WCAG AA（正文 4.5:1） |
  | --- | --- | --- |
  | `inkMute` rgba(63,74,90,.52) | **2.63:1** | 不达标 |
  | 水果 `inkMute` | **3.27:1** | 不达标 |
  | `amber #E39A32` | **2.35:1** | 不达标 |
  | `teal #0F9C8C` | **3.41:1** | 不达标 |
- **建议**：辅助文字最小 10.5px、正文 12px；`inkMute` 透明度提到 0.62（≈4.0:1）或直接换 `#5A6675`；
  琥珀/青色只用于色块和图形，不承担文字信息。

### 6. 三个游戏页面没有页面级测试
- **证据**：只有 `tools/shoot-ui-test.js` 覆盖 `pages/shoot`；fruit / wire / rhythm 的 `initCanvas`、BLE 回调、触摸分发、`onUnload` 都没有测试。
- **风险**：之前踩过的「画布尺寸不跟随布局」「遮罩画在 dpr 变换外」「漏接果子卡住」都在这层。
- **建议**：把这套页面桥接抽成工厂后，用一个假 `Page`/假 `wx` 给三个游戏各补 10~15 项（尺寸变化、暂停/恢复、断线、卸载清理）。

### 7. 定时器未随页面销毁清理
- **证据**：`pages/rhythm/rhythm.js:125`（initCanvas 重试）、`:155`（fitCanvas）的 `setTimeout` 没有句柄；
  fruit / wire / rhythm 三个页面的 `onUnload` 里 `clearTimeout` 计数为 0（shoot 有 1 处）。
- **建议**：统一存句柄，`onHide`/`onUnload` 清理；或复用 shoot 那套 `sizeWatch`。

### 8. `app.js` 是空的
- **证据**：`app.js` 只有 `App({})`。
- **风险**：线上白屏、引擎异常、音频失败都没有任何上报入口，只能靠用户描述。
- **建议**：加 `onError` / `onUnhandledRejection`，把「游戏 id + 版本 + 错误栈」写进本地日志环（最多 50 条），
  在「我的」页留一个导出入口给治疗师反馈。

### 9. 蓝牙无自动重连
- **证据**：`utils/witble.js:124` 只监听了连接状态变化，没有重连策略。
- **影响**：治疗中途传感器掉线，患者要退出游戏回连接页。
- **建议**：断开后按 1s/2s/4s 退避重连 3 次，失败再提示；重连成功自动 `resume`（现有状态机已支持）。

## P2 · 可维护性（收益最大的一块）

### 10. 三个渲染器各重复约 250 行公共控件
- **证据**：`_text` / `_measure` / `_button` / `_icon` / `_glass` / `_panel` / `_dot` 在 3 个渲染器里各有一份：
  fruit 256 行、wire 248 行、rhythm 235 行；fruit 与 wire 的**相同非空行占 21.5%**。
- **建议**：抽 `games/ui-kit.js`（文字/按钮/图标/卡片/圆角矩形，含 dpr 与主题色注入），三个游戏共用。
  预计每个渲染器减 250 行，且以后改按钮样式只改一处。

### 11. 三个配置 store 近乎同构
- **证据**：`fruit-config.js` 410 行、`wire-config.js` 413 行、`rhythm-config.js` 379 行，
  都是「SCHEMA + clamp 校验 + get/patch/set/load/save/reset/subscribe/emit + 延迟落盘」。
- **建议**：照 `training-record.js` 的做法抽 `createConfigStore({ key, schema, presets })`，各游戏只留自己的 SCHEMA 与预设。

### 12. 页面桥接代码重复
- **证据**：`initCanvas` / `attachBle` / `onTouchStart` / `onTouchEnd` / `dispatch` / `getDpr` 各 4 份；
  `startLoop` / `stopLoop` / `handleEvents` / `persistRecord` 各 3 份。
- **建议**：`createGamePage({ engine, renderer, clock, records })` 工厂，页面只写差异（曲目表、结算字段）。

### 13. 设置页 / 记录页重复
- **证据**：4 个 settings（146~237 行）+ 3 个 records（198~230 行）结构一致，都是「概览 → 分组 → 滑块/开关 → 保存」。
- **建议**：抽 `<param-group>`（按 SCHEMA 渲染）与 `<record-list>` 两个组件，页面只传 schema 与记录库。

### 14. 没有 package.json / CI
- **证据**：仓库根目录没有 `package.json`，6 套自检（约 2900 行）只能手敲 `node tools/xxx.js`。
- **建议**：加 `"scripts": { "test": "node tools/run-all.js" }` 与最小 GitHub Actions（node 22，跑全量自检），
  每次提交自动跑——这套自检本来就写得很好，白放着可惜。

## P3 · 打磨项

15. **命名不统一**：`pages/rhythm-records`、`rhythm-settings` 里仍写「左右节奏训练」，游戏内 HUD 已改「节奏训练」；
    目录 `wire` 对应中文「走钢丝」，README 与页面标题混用。建议统一一份「游戏显示名」常量。
16. **魔法数字双份**：如 `approachMs` 在 config 里 min 900 / max 4000，引擎里却 `clamp(..., 600, 4000)`；
    `CATCH_LINE / MISS_AFTER / REMOVE_AFTER` 散在文件顶部。建议单一来源，引擎只读 config 的 min/max。
17. **`race/` 的页面图标与文案**与其他游戏风格不一致（其余已统一为清新风），若保留建议同步。
