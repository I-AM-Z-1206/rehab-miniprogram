# 左右节奏训练 · 体感康复小游戏（rhythm）

WT9011 **卡在胸带上**（胸带从**腋下最高点**绕一圈固定），标定中立位后，身体左右偏移 → 归一化控制量 `nx ∈ [-1,1]` →
判定当前处于**左 / 中 / 右**哪个区域（三车道：中向音符要求「回到中立位」）。音符按 BPM 精确生成，
玩家在音符到达判定线时把身体保持在正确一侧即为命中；方向和时间各算一项指标。

## 2. 状态机

```
IDLE(intro) ─start→ READY(prepare) ─calibrate→ CALIBRATING
                       │                          │
                       └─────enter──────▶ COUNTDOWN（预备拍 4 拍）
                                                 │ 音乐开始
                                                 ▼
                            PAUSED ◀──pause──▶ PLAYING ──timeout/quit──▶ RESULT / ABORTED
                                                 │
                                    SENSOR_ERROR ◀─断线/超时
                                        │
                                        └─resume（数据恢复）→ PLAYING
```

* 只有 `PLAYING` 会推进音乐时间与判定；`PAUSED` / `SENSOR_ERROR` / `RESULT` 全部冻结。
* `finish()` 只结算一次（`settled`），重复调用不会重复加分。
* 断线**不会**自动切模拟，也不会把漏掉的音符判成命中。

## 3. 时间基准与音画同步

* 主时钟：`performance.now()`（单调递增），**不用帧数累加**。
* 音频 `currentTime` 只用于纠偏：偏差 > 80ms 硬纠正，否则按 5% 软拉。
* 音频 `loop` 播放时 `currentTime` 回绕，用回绕检测累计 `loopCount`，
  得到连续音乐时间；循环长度 = 整数小节，因此不会累积漂移。
* 暂停：记录 `pausedAt`，恢复时重设锚点，音频从暂停点继续。
* 判定时间 = `音乐时间 − syncOffsetMs`；视觉位置用音乐时间。
  `syncOffsetMs > 0` 表示"听到比看到晚"，在准备页用「试听 8 拍」校准。
* 音频不可用 → `silent` 模式：时钟照跑，界面显示「无音乐」，**不声称与音乐同步**。

## 4. 谱面

```js
{ noteId, targetSide: 'left'|'right', beatIndex, targetTimeMs, noteType, scoreValue }
```

* `targetTimeMs = offsetMs + beatIndex × (60000 / BPM)`，单位毫秒。
* 生成规则（`buildChart`）：从第 `prepBeats` 拍开始，每 `noteStepBeats` 拍一个音符；
  左右交替为底版，按 `centerRate` 概率换成中向音符（要求回到中立位），
  按 `sameSideRate` 概率出现同向连续；小节第一拍标为 `accent`（分值 120）。
  `centerRate = 0` 时退化为纯左右两车道。
* **呼吸拍是固定间隔，不是随机**：`restRate` 表示"每 N 个音符空一拍"
  （`N = round(1 / restRate)`，最小 4）。这样间隔只可能是「1 个步长」或「2 个步长」，
  不会出现"连着空两三拍 → 一堆音符之后半天没一个"的手感。
* **同向连续必须间隔 ≥ `sameSideGapMs`**，否则生成时强制换向 —— 否则在"一次动作只结算一个音符"的规则下玩家根本打不出来。
* 同曲 + 同难度 + 同种子 + 同算法版本 → 完全相同的音符时间表（训练可对比）。
* `parseChart()` 可读取外部 JSON，逐条校验方向/时间/ID 重复，不合法只报错不静默丢弃。

## 5. 身体输入

复用 `utils/motion.js`（死区 → 归一化 → 一阶低通 → 方向滞回），只消费：

* `nx ∈ [-1,1]`：归一化控制量（不是厘米位移）
* `dir`：`left` / `center` / `right`，阈值由 `sideThreshold` 决定
* `stale`：> 1.2 秒没有新帧 → 立即进入 `SENSOR_ERROR`

游戏再叠一层"动作事件"：

* `enterAt`：这一侧是什么时候进入的（用于算节奏误差）
* `stableMs`：进入后保持多久（`stableMs` 之前不算命中，过滤路过抖动）
* `actionSeq`：进入动作的序号；**一次动作最多结算一个音符**
  例外：保持同一侧时，距上次命中 ≥ `sameSideGapMs` 可再次命中（避免"一直站着刷分"）

## 6. 判定规则（hit-judge.js）

```
音符到达判定线（targetTime）之前：一律不判 —— 提前站好不算准
到达之后：
  · 方向错误且已稳定      → MISS（记 wrongDirection，同时断连击）
    （中向音符例外：回中路上必然经过两侧，给满整个窗口再判方向错误，
     窗口内回到中间按迟到正常判，避免误伤正在正确移动的患者）
  · 方向正确 + 稳定 + 动作可用：
        时间误差 = 进入该侧的时刻 − 目标时刻（提前站好最多算到窗口边缘）
        |误差| ≤ perfectMs → PERFECT
        |误差| ≤ greatMs   → GREAT
        |误差| ≤ goodMs    → GOOD
  · 超过 goodMs 仍未就位  → MISS（late / no-input / no-new-action）
```

判定窗口全部可配（`perfectMs < greatMs < goodMs`，校验会拦截顺序错误），
颜色、英文名、中文名、图形标记四者同时呈现，不只靠颜色区分。

## 7. 计分

```
单音符得分 = 音符分值 × 连击倍率
连击倍率   = min(comboMaxMul, 1 + max(0, combo-1) × comboStep)
总分       = 基础分合计 + 连击加成合计 + 完成奖励

节奏准确率 = (PERFECT×1 + GREAT×0.7 + GOOD×0.4 + MISS×0) / 已判定数
方向准确率 = 命中数 / (命中数 + 方向错误数)
综合命中率 = 命中数 / 谱面音符总数
```

分母为 0 一律返回 `null`，界面显示「暂无数据」（不会冒充 100%）。

## 8. 难度与配置

默认节奏：66 BPM、**每拍一个音符**（约 0.9 秒来一个）、休止拍 12%、预备拍 2，
飞行时间 2.6 秒 —— 音符看着长、来得连贯，不会"半天才来一个"，也不会快到反应不过来。
1~5 档预设只覆盖手感参数（音符间隔 2 / 1.5 / 1 / 0.75 / 0.5 拍、休止比例、判定窗口、
飞行时间、时长、预备拍），体感输入与曲目选择保持治疗师设置。可调项：

* 音乐：曲目（静水深流 66 / 晨光漫步 90 / 心跳律动 110 BPM）、音量、音画补偿、节拍脉冲、节拍点击音
* 训练目标：时长、预备拍
* 体感输入：左右轴、反向、灵敏度、死区、跟手度、左右边界
* 左右判定：区域阈值、稳定判定时间、同向重复间隔
* 节奏判定：三档窗口、飞行时间、音符间隔、中间音符比例、休止比例、同向比例、谱面种子
* 计分：三档分值、连击步长/上限、漏接是否断连击、完成奖励
* 反馈：音效、语音、振动、引导提示

## 11. 性能与异常

* 静态背景（夜空 + 极光 + 暗角 + 三色车道 + 网格）离屏缓存，每帧只 `drawImage` 一次；`drawImage` 必须显式给目标宽高。
* 每帧新增的动态层控制在低开销范围：12 条车道流光（描边）、判定线柔光（1 个渐变）、
  每个音符 3 节拖尾菱形 + 1 个外圈描边、3 块地台底光（3 个径向渐变）。
* 高频传感器数据只写进 `MotionTracker`，页面**没有任何逐帧 setData**。
* 音符按时间游标加入 `active`，判定后保留 700ms 淡出再回收，并有上限保护。
* 页面隐藏：停帧循环 + 暂停音乐 + 停语音；卸载：结算落记录、销毁音频、断开共享蓝牙。

### 真机验收步骤

1. 连接 WT9011（50Hz）→ 准备页显示「传感器已连接 / Hz」。
2. 中立位 3 秒完成标定 → 点「试听 8 拍」调音画补偿，让闪烁与听到的拍子重合。
3. 开始 → 先听 4 拍预备，音乐开始后按拍左右移动；音符到判定线时保持在正确一侧。
4. 暂停：音乐、音符、判定、计时全部停住；恢复后不跳帧、不重复计分。
5. 关掉传感器：进入「传感器数据中断」，不判定、不加分；重连后可继续，结算里带中断时长。
6. 结算：分项之和 = 总分；三个准确率公式与记录页一致；无样本显示「暂无数据」。

## 13. 待真机确认

* **轴向与正负**：默认 `axisX = pitch`、`invertX = true`，换佩戴方向可能要改（设置页可改，立即生效）。
* **音画同步**：不同机型/蓝牙耳机延迟不同，必须用「试听 8 拍」现场校准；补偿值会写进记录。
* **判定手感**：`sideThreshold`（0.35）、`stableMs`（120ms）、`goodMs`（160ms）是按 90/110 BPM 估的初值，需按患者能力微调。
* **同向连击间隔**（320ms）：若患者保持一侧的稳定性差，可上调该值减少"来不及重新进入"的漏接。
* **音轨格式**：打包用的是 **22.05kHz 单声道 AAC（.m4a）**，三首合计约 300KB（静水深流 66 / 晨光漫步 90 / 心跳律动 110 BPM）；wav 是同参数中间产物，循环边界零跳变，只用于转码、不进包。
  转码命令写在 `tools/gen_rhythm_audio.py` 头部；若某机型循环有缝，先在真机确认再考虑换编码与重新校正循环长度。
* **上报接口**：需在设置页填 https 地址与令牌；隐私清单与同意流程已就位。

界面走「奶油白 + 糖果色」，不用霓虹/发光：

* 背景：浅天蓝 → 奶油白渐变，太阳、圆角云朵、远景丘陵与小树、飘落花瓣、空中光斑；
* 跑道：奶油路面 + 三色车道，路缘彩色描边 + 白色内线，路面两侧有柔和外投影；
  每一拍一条横向节拍线顺路流向判定线；
* 跑道：奶白色路面，三条车道分别染草莓粉 / 蜂蜜黄 / 薄荷绿，白色圆头虚线分道；
* 音符：圆角方块糖（不是菱形），白描边 + 顶部高光 + 拖尾；左粉 / 中黄 / 右绿；
  方向用「双雪佛龙」而不是实心三角（实心三角会被读成播放键），中间音符用白点标记；
* 目标提示：下一颗音符进入后半程时，它所在的车道会浮出一段透视柔光，视线自动跟过去；
* 判定地台：白色胶囊 + 糖果色描边 + 软阴影，选了哪侧就轻轻抬起；
* 玩家：白色小团子（眼睛 + 腮红 + 微笑），在三个刻度之间移动；
* 文字：深蓝灰 `#3F4A5A` 白底可读；判定字用深色版配色（`VERDICT_INK`）+ 白描边。

配色集中在 `games/rhythm/renderer.js` 顶部的 `C`，改主题只改这一个对象。

## 15. 节奏跟不上 / 断断续续 / 音符堆积（2026-10-30 修正）

实际试玩反馈：「左右变化太快，我自己都跟不上」「音符一下好多、一下没有」「音符停留有问题」。
三条都能落到具体数字上，不是手感-tuning 能解决的。

### 15.1 根因：难度是按拍数定义的，BPM 一变难度就漂移

`noteStepBeats` 是**拍数**（相对量）。同一个「标准」档：

| 曲目 | BPM | 难度 3 的实际间隔 |
| --- | --- | --- |
| 静水深流 | 66 | 909 ms |
| 晨光漫步 | 90 | 666 ms |
| 心跳律动 | 110 | **545 ms** |

治疗师选同一档难度，换个曲子速度差 1.7 倍。而康复患者完成一次左右转移再稳定下来
大约需要 700ms 以上 —— **545ms 的间隔在数学上就不可能命中**，患者只能一路漏接。

改法：新增 `minGapMs`，谱面生成时以**毫秒**为目标，从合法拍值
`[0.5, 0.75, 1, 1.25, 1.5, 2, 2.5, 3, 4]` 里挑换算后最接近的那个。
音符仍然落在拍点上（音乐性不丢），但绝对间隔进入安全区。
另设 620ms 硬下限兜底。

> 先试过「不够就整倍数放大」，粒度太粗：66 BPM 的 909ms 会被直接翻到 1818ms，
> 明明只差 9% 却慢了一倍。

修正后难度 3：909 / 1000 / 1090 ms（漂移 1.67× → 1.20×）；难度 5：666~681 ms（1.02×）。

### 15.2 根因：判定在惩罚「提前移动」

时间误差 = 进入该侧的时刻 − 拍点，而 early 和 late 用**同一个**窗口。

但躯干不是按键 —— 它必须**提前启动**才能准时到位，移动本身就要几百毫秒。
所以「早于拍点进入」是唯一的、正确的策略，不是失误。
原逻辑下患者做对了（提前启动、准时到位）却被判 MISS。

改法：新增 `earlyFactor`（默认 1.8），**只放宽 early 一侧**，late 保持严格
（那才是真的跟丢了节奏）：

| 提前量 | 改前 | 改后 |
| --- | --- | --- |
| 150 ms | GOOD | PERFECT |
| 250 ms | **MISS** | GREAT |
| 350 ms | **MISS** | GOOD |
| 450 ms | MISS | MISS |

迟到侧不变：迟到 250ms 改前改后都是 MISS。

### 15.3 根因：休止拍让间隔突然翻倍

原来「每 N 个音符空一拍」，空的位置落在小节中间，效果是间隔从 666ms 跳到 1333ms
—— 患者刚建立起来的节奏预期被整段打断，主观感受就是「一下子好多、一下子又没有」。

改法：休止**只在小节末尾**留空（用 `floor(b/bar)` 判断跨小节，不用浮点取模 ——
step 是 0.75 这类值时 `(b+step) % beatsPerBar` 永远不会正好落在 0 上，休止就再也不触发了），
并按小节计数。同时把各档 `restRate` 下调（0.28/0.2/0.12/0.08/0.06 → 0.2/0.14/0.08/0.06/0.04），
减半休止次数。

### 15.4 根因：停留时间比音符间隔还长

`NOTE_TAIL_MS = 700`，而标准档音符间隔只有 666ms —— 下一个音符都到了，
上一个还堆在判定线上，患者看不出该看哪一个。

改法：降到 380ms；并且让过了线的音符**继续往前走一小段**再淡出，而不是停在判定线上
（`_noteY` 里 `p > 1` 时继续下移 30%）。停住的话密集谱面上判定线附近会糊成一团。

### 15.5 顺带修掉的偏侧 bug

`chart.js` 的交替逻辑 `lastSide === 'left' ? 'right' : 'left'` ——
当 `lastSide === 'center'` 时走 else 分支，**恒取 left**。
所以每个中间音符之后必然是左侧音符，实测左比右多 14~32%，康复训练最忌讳左右不对称。

改法：交替基于**上一个非中间音符**（`lastNonCenter`）判断。修正后左右差 ±4 以内。

### 15.6 五档难度的新参数

每档都带 `minGapMs`（毫秒下限），判定窗口整体放宽：

| 档 | minGapMs | perfect/great/good | restRate |
| --- | --- | --- | --- |
| 1 入门 | 1600 | 110 / 180 / 260 | 0.20 |
| 2 轻量 | 1250 | 95 / 160 / 235 | 0.14 |
| 3 标准 | 1000 | 85 / 145 / 210 | 0.08 |
| 4 进阶 | 820 | 75 / 128 / 190 | 0.06 |
| 5 挑战 | 680 | 65 / 112 / 170 | 0.04 |

`chartSeedVersion` 从 `v2` 升到 `v3`：谱面生成算法变了，旧种子会重新生成，
同一患者的训练记录**不与改版前直接可比**，做前后对比时要注意。

## 16. 音符节奏与音乐解耦（2026-10-30 定版）

**结论：音符不再跟着音乐拍点走，节奏由毫秒直接给定。**

### 16.1 为什么要解耦

上一轮（第 15 节）用「毫秒下限 + 吸附到最近拍值」把漂移从 1.67 倍压到 1.20 倍，
但**只要音符必须落在拍点上，BPM 就仍在决定训练强度**：

| 档位 | 66 BPM | 90 BPM | 110 BPM |
| --- | --- | --- | --- |
| 标准（旧） | 909ms | 1000ms | 1090ms |

三档看着接近，是因为它们都被迫从 `[0.5, 0.75, 1, 1.25, 1.5, 2, 2.5, 3, 4]` 里挑
——**能取的值本来就被拍值离散化了**，想给 1150ms 只能取 1000 或 1250。
治疗师其实根本不打算让音乐参与难度决策，是 BPM 自己挤进来的。

康复训练里音乐是背景，不是考官。患者该多久动一次，取决于他完成一次重心转移
需要多久，跟这首曲子多少 BPM 没有任何关系。

### 16.2 改法

`buildChart()` 拆成两步，**两种模式只差第一步**：

1. **算时间点**
   - 自由模式（默认）：`t = prepMs`，然后 `t += gapMs` 直接推进，与 BPM 无关；
   - 吸附模式（`snapToBeat`）：从合法拍值里挑换算后最接近 `noteGapMs` 的，音符仍在拍点上。
2. **分配方向**：左右交替 / 中间音符 / 同向连续 —— 两种模式共用同一套规则。

新增参数：

| 参数 | 默认 | 说明 |
| --- | --- | --- |
| `noteGapMs` | 1100 | **训练强度的主参数**，两个音符之间隔多少毫秒 |
| `snapToBeat` | false | 打开才吸附拍点；关闭时严格按毫秒走 |
| `prepMs` | 2400 | 开头留白，建议 ≥ 音符飞行时间，否则第一个音符会「半路冒出来」 |

`noteStepBeats` 保留，但**只在 `snapToBeat` 打开时生效**。
`minGapMs` 退役（语义从「下限」变成「目标间隔」，已并入 `noteGapMs`）。

### 16.3 呼吸改成「拉长间隔」，不再「跳过音符」

原来休止是跳过一个音符，间隔直接翻倍（666 → 1333ms）。患者刚建立起来的节奏
预期被整段打断，主观感受就是「一下子好多、一下子又没有」——这是用户原话。

改成把间隔拉长到 **1.5 倍**（`BREATHE_FACTOR`）：音符一个不少，只是慢半拍，
节奏不断线。合法间隔从此只有两种值：`gapMs` 与 `gapMs × 1.5`。

### 16.4 物理下限 620ms

`HARD_MIN_GAP_MS = 620` 兜底：低于这个值，多数患者一次左右转移都做不完，
只能一路漏接。即使治疗师把 `noteGapMs` 拉到 400，实际也不会低于 620。

### 16.5 视觉提示必须跟着音符，不能跟着拍点

这是解耦后最容易漏的一处。判定线 / 踏板 / 光柱的呼吸原本用 `clock.beatPhase()`
驱动，解耦后会出现「灯在拍点上闪、音符在别的时候到」，患者照着灯动反而全错。

新增 `engine._notePhase()`（0 = 下一个音符还很远，1 = 马上到），三处呼吸全部改用它。
顺带把按钮文案「节拍开/关」改成「提示开/关」——它提示的是音符，不是节拍。

`beatClickOn`（拍点点击音）默认改为关闭：它按音乐拍点响，与「该动了」的时刻无关。

### 16.6 五档预设（毫秒）

`noteGapMs` 按「一次重心转移要多久」定，不按拍数定：
患者完成一次左右转移 + 稳定判定约需 700~900ms，所以入门档留两倍余量，
挑战档才压到 780ms。

| 档 | noteGapMs | perfect/great/good | prepMs / approachMs | restRate |
| --- | --- | --- | --- | --- |
| 1 入门 | 1800 | 110 / 180 / 260 | 3000 / 3000 | 0.20 |
| 2 轻量 | 1450 | 95 / 160 / 235 | 2800 / 2800 | 0.14 |
| 3 标准 | 1150 | 85 / 145 / 210 | 2600 / 2600 | 0.08 |
| 4 进阶 | 950 | 75 / 128 / 190 | 2400 / 2400 | 0.06 |
| 5 挑战 | 780 | 65 / 112 / 170 | 2200 / 2200 | 0.04 |

### 16.7 验证：患者模型跑完整一局

新增 `tools/rhythm-playability-test.js`（29 项）：模拟患者只会提前启动 + 0.35s
缓动移动，跑完整一局。结果：

| 难度 | 66 / 90 / 110 BPM 音符数 | 提前 250ms | 提前 400ms |
| --- | --- | --- | --- |
| 1 入门 | 42 / 42 / 42 | 100% 命中 | 100% 命中 |
| 3 标准 | 71 / 71 / 71 | 100% 命中 | 100% 命中 |
| 5 挑战 | 106 / 106 / 106 | 100% 命中 | 100% 命中 |

**三首曲子音符数完全一致** —— 换曲子不再改变训练强度，这是本次的核心指标。
判定仍有区分度：提前 250ms 时难度 5 只有 15~21 个 PERFECT（其余 GREAT/GOOD），
提前 400ms 则全掉到 GOOD，不是无条件满分。

### 16.8 影响

- `chartSeedVersion` 从 `v3` 升到 `v4`：谱面算法变了，
  **改版前后的记录不可直接对比**。
- 治疗师设置页的「音符间隔」单位从「拍」变成「毫秒」，预设对比表同步改。
- 吸附模式保留给「想让动作跟音乐走」的场景，代价是换曲子难度又会漂移
  （测试里有对应断言把这个代价钉住）。
