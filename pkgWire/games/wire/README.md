# 走钢丝（WR-01）· 体感平衡训练小游戏

固定高空场景的 2D 走钢丝。患者把 WT9011DCL 卡在胸带上（胸带过腋下最高点），用身体的左右/前后偏移
控制角色平衡，沿钢丝前进；越界时由「保险绳」扶稳，而不是直接判负。

> 本目录只放游戏逻辑与渲染，页面在 `pages/wire/`，传感器与记录在 `utils/`。
> 所有参数都是**待真机实测的游戏参数**，不代表医疗安全区间，也不构成康复疗效结论。

## 二、状态机

```
IDLE ──开始训练──▶ READY ──标定──▶ CALIBRATING ──▶ READY
                      │
                      └──进入游戏──▶ COUNTDOWN ──3s──▶ PLAYING
                                                       │  ├─▶ PAUSED ──继续──▶ PLAYING
                                                       │  ├─▶ SENSOR_ERROR ──数据恢复──▶ PLAYING
                                                       │  └─▶ RESULT / ABORTED
```

* 计时用 `Date.now()` 的真实间隔累加，暂停与传感器中断期间不累加。
* 结算只执行一次（`score.settled` + `recordId` 去重），刷新/重复结算不会重复加分。
* 退出、返回、页面卸载时按 `aborted` 结算，记录标记「未完成」。

## 三、控制量与归一化

```
nx ∈ [-1, 1]   左右（-1 左，+1 右）
ny ∈ [-1, 1]   前后（-1 后，+1 前）
nx = angleX * 灵敏度 / 对应侧边界      （到 ±1 即到达治疗师设定的边界）
```

**这是游戏控制量，不是厘米、不是米、也不是重心位移。** 角度也不等于真实空间位移，
所以轨迹长度、摆动分布、平均运动速率都标注为「姿态代理指标」。

默认轴向（来自本项目射击页 / 赛车页的实机反馈，仍需真机复核）：

| 用途 | 轴 | 反向 |
| --- | --- | --- |
| 左右 `nx` | `pitch` | 是（角色与身体同向时关闭 `invertX`） |
| 前后 `ny` | `roll` | 否 |

改轴向不改代码：`tools/…` 或治疗师页的「体感输入」分组里改 `axisX / axisY / invertX / invertY`。

## 四、平衡模型

```
load = max(|nx|, 0.75·|ny|)
offset 在舒适区（load ≤ 0.18）：balance += (recovery × (1 - balance) + 0.05) × dt
超出舒适区：             balance -= (load-0.18)^1.35 × instability × (1 + 偏移时长/6 × 0.35) × dt
保险绳介入时：           balance 不低于 0.22（托底，不再恶化）
```

* `balance = 1` 完全稳定，`0` 即将失稳；不是二元判断，是连续值。
* 前进速度 `= 前进速度 × (0.35 + 0.65·balance) × 前后系数`，失衡自动减速，不靠随机或突加难度。
* 稳定判定：`load < 警戒阈值 × 0.82` 且 `balance > 0.55`。

## 五、保险绳

| 阶段 | 触发条件 | 表现 |
| --- | --- | --- |
| WARN | `load ≥ 警戒阈值` | 边缘暖色渐晕 + 文字提示，不扣分不停游戏 |
| ENGAGED | `load ≥ 触发阈值` 且已过冷却 | 绳索绷直、金色光环、控制量被抑制 `ropePull`、平衡托底，**不结束本局** |
| RECOVERING | `load ≤ 解除阈值` | 保持 `ropeHoldMs` 后解除 |
| IDLE | 解除完成 | 冷却 `ropeCooldownMs`，防止边界反复触发 |

* 关闭保险绳时按 `failRule` 处理：`penalty`（越界期间不前进 + 扣分）或 `terminate`（结束本局）。
* 触发次数、介入时长写进结算与训练记录；触发**不会清零**本局得分（默认只扣 `penaltyScore`）。

## 六、计分

```
总分 = 距离 × 每米分
     + Σ(每秒稳定分 × 连击倍率)     连击倍率 = min(1 + 连击级数 × comboStep, comboMaxMul)
     + 走完全程奖励
     - 越界 / 介入扣分
```

分项在结算页与训练记录里逐项列出，便于核对；相同配置 + 相同操作 → 结果一致（无随机数）。

## 七、怎么测试

1. **无设备（模拟模式）**：游戏页 →「打开模拟数据」→ 设备准备页标定会自动跳过 →
   进入游戏。左侧一组按钮可调左右/前后、回中、直接把偏移拉到边界测试保险绳。
   画面左上角常驻「模拟数据」标记，记录里的 `dataSource = simulation`，**默认不上报**。
2. **无头自检**（不需要微信开发者工具）：

   ```bash
   node tools/wire-headless-test.js
   ```

   覆盖状态机、稳定通关、持续失衡、关闭保险绳越界、暂停计时、四个界面的渲染冒烟、
   小屏/大屏适配、记录防重复与模拟数据标记。
3. **真机**：
   * 首页连接 WT9011 → 进游戏 → 设备准备页 → 静置 3 秒标定（晃动会判定失败并提示重来）。
   * 左右移动身体，确认角色倾斜方向与身体一致；不一致就改 `invertX`。
   * 前倾 / 后倾应影响前进速度；相反就改 `invertY`。
   * 走到边界，确认保险绳介入而不是直接失败；回正后应自动解除。
   * 训练中关掉传感器电源，确认进入「信号中断」并暂停计时，重新开机后自动/手动继续。
4. **参数生效**：训练设置里改边界/阈值/速度，返回游戏后立即生效（配置在每帧读取）。

## 八、仍需真机确认的问题

1. **轴向与正负**：`axisX=pitch / invertX=true` 来自既有页面的实机反馈，走钢丝的佩戴角度
   可能不同，必须按上面的步骤复核。
2. **标定静止判定阈值**（标准差 2.6°、峰峰 9°）是否适合手抖明显的患者，需要实测调整。
3. **保险绳阈值**（默认 `warn 0.66 / trigger 0.88 / release 0.52`）在小幅度患者身上的手感。
4. **输出频率**：页面请求 50Hz（硬件离散档位），低端机丢包率与 `quality` 指标需要观察。
5. **上报接口**：项目里没有既有的后端上传地址，本模块只提供「配置地址 + 同意后上报」的通道，
   未配置时记录仅保存在本机，界面上如实显示「未配置」，不会伪造上传成功。

## 九、画面与透视（实现要点）

| 环节 | 做法 |
| --- | --- |
| 深度 | `p = 1 - 1/(1 + r/D)`，`D = 5.2`；`y = charY - (charY - farY) * p`，线宽 `∝ (1-p)^0.92` |
| 脚底线 | `charY = min(H*0.775, H-170)` —— 短屏上移，避免底部平衡条压住脚 |
| 消失点 | `farY === horizonY === H*0.335`。钢丝 / 安全走廊 / 里程灯共用这一个点；**两个值不等就会出现「钢丝停在半空」** |
| 钢丝采样 | `p` 从 `-0.62`（已越过画面底边，不会出现悬空断口）到 `1.0`（正好落在地平线上） |
| 远端淡出 | **按 56 个切片逐段填 alpha**（`fadeAt` 在 `p>0.90` 之后 smoothstep 掉到 0.18）。分 4 个固定档会在边界留下宽度与亮度台阶，手机上读成「钢缆被切成几截」 |
| 钢丝剪影 | 整条一次画完，透明度交给竖向渐变；不要按段画——每段一个 `pad` 就多一条横向接缝 |
| 灭点融合 | 地平线处盖一团暖白径向（半径 `0.036W`、峰值 0.58），钢缆才是「化进雾里」而不是「插进地平线」 |
| 地面 | 谷底渐变**第一档必须等于天空最底部颜色**（现 `rgba(10,28,43,.88)`），否则地平线是一条硬边。这条比加任何雾都管用 |
| 云海 | **5 条分形云脊**，每条从左到右起伏、向下填到画面底部，越近越暗；脊上两道柔光带（9px + 2.4px），脊下压一道冷影。见第十节 |
| 角色 | **背影**（不是正面）。平衡杆画在躯干之前、被身体遮住中段；背带在肩胛处 X 交叉，绳索挂环就在交叉点上。见第十节 |
| 里程灯 | 串在钢丝上的**灯珠**（`cx` 上），亮 = 暖金、灭 = 冷白，10 的倍数用大一号的珠子。灯珠只做「刚走过这一点」的即时反馈 |
| 里程界桩 | 每 10 米一根，立在**钢丝两侧的云海里**（不在钢缆上），牌面写米数；终点桩金色 + 双柱 + 最后 8 米呼吸光晕。见第十二节 |
| 保险绳 | 锚点在 `cx + 0.26W`、`anchorY = -26`、带明显垂度。平时 `ropeGrad([38,44,58],0.14)` 几乎不可见，吃上力才转暖金。笔直的米色亮线在逆光天空上就是一道划痕 |
| 结算页 | 不画角色与保险绳（卡片占满屏，只露两条腿 = 「有人躲在板子后面」）；里程碑飘字只在 `play` 画 |
| 静态背景 | 天空 / 云 / 远山 / 山谷烘焙到离屏 canvas（`wx.createOffscreenCanvas`），失败时直接绘制 |

## 十、矢量角色（背影）与走路循环 —— 现在只用兜底

> v4 之后正式绘制走的是第十三节的 3D 序列帧；这一节描述的矢量绘制仍然完整保留，
> 是 `wx.createImage` 失败时的兜底路径，也是「背影该怎么画」这套判断的来源。
>
> **v5 已经把矢量兜底也换成了提灯旅人**：调色板换成暖赭、删掉背带（`drawHarness` 变成
> 空实现）、平衡杆换成 `drawLantern`、头部从「颅骨 + 头发」改成「兜帽」。
> 换的过程中有三条只有 2D 平涂才会踩到的坑，记在这里：
>
> - **不能画那条「帽檐」弧线**。3D 版兜帽下沿有一圈翻出来的边，照搬到 2D 是一条横贯
>   头部下缘、两端上翘的亮弧 —— 读成**礼帽**。3D 能成立是因为那道边有厚度、下面还压着
>   披肩；2D 只有一条线，线就是帽檐。
> - **不能露米色脖子**。9px 的皮肤色脖子 + 兜帽 + 领口，三件事拼起来必然读成
>   「一个人戴着礼帽」。改成兜帽的暗色（等于领口里的阴影），和 3D 版一致。
> - **兜帽要比头大一圈**（`r * 1.08`）。同尺寸会读成「头就是这个形状」。

场景是伪 2.5D 第一人称，镜头在角色**正后方**。所以角色必须是背影——
前几版画的是正面（有眼睛、鼻子、嘴），镜头看到角色在往前走、角色却把脸对着后面，
方向是反的；顺带，脸也会邀请人去读表情（和射击靶子从「大眼外星人」改成机械哨兵同一条教训）。

### 背影带来的三处连带改动

| 部位 | 做法 | 为什么 |
| --- | --- | --- |
| 平衡杆 | 画在**躯干之前**，中段被身体挡住，只露两端和两只手 | 「杆在身前」是背影唯一能建立纵深的东西；画在身后就成了正面 |
| 安全背带 | 背部 X 交叉，两条带子都过 `(0, hookY)`，挂环就画在交叉点 | 前几版挂在胸前；绳子从胸骨往上拉，背影下一眼假。挂环不在交叉点上会「浮在背上」 |
| 头 | 头发覆盖整个后脑、后颈露 4~5px、耳朵只露外侧一线、**没有五官** | 纯球形后脑会被读成头盔；耳朵画大了就是一副耳机 |

### 走路循环的四条硬规则（`tools/wire-preview/char-lab.html` 逐帧核对）

1. **任何时刻至少一只脚在钢丝上**。抬脚量取 `max(0, sin)`，两腿相位差 π，天然互斥。
2. **抬脚要同时变高、变小、向外**。只改高度读成「上下抽搐」；三样一起改才读成「脚往前迈出去」。
3. **身体起伏（bob）频率是步频的两倍**。`|cos|` 在双腿并拢时最大（最高）、单脚支撑中段为 0。写成 `|sin|` 会和脚落地同相，走起来像在蹦。
4. **脚要钉在钢丝上**。身体左右摆（`swayX`）时脚不能跟着平移，否则读成「整个人在钢丝上滑」。做法是脚坐标反向补偿 `swayX` 的 80%。

### 角色上踩过的坑

| 现象 | 真因 | 修法 |
| --- | --- | --- |
| 后脑像戴了顶贝雷帽 | 头发下缘是横贯 0.7r 的弧（帽檐形状），且**头发比颅骨小一圈**，露出一圈皮肤色的「头皮」 | 下缘收窄到脖子宽度（±0.34r），并且在下缘必须比颅骨更靠外 |
| 头顶像镶了金边 | 轮廓光用 `stroke` 描了一整圈 | 改成 clip 到头发后打一片**面光**，边缘光只 1.1px 且两头收掉 |
| 头直接坐在衣领上 | `headCY` 只保证头顶高度，头底比颈根高 4px，脖子被头发盖死 | `headCY` 必须让「头底 ≈ neckY」 |
| 一对「护肩」 | 手臂起点在肩点外侧（±0.96×肩宽），圆头凸出躯干 4px | 肩点收到躯干轮廓里（±0.70×肩宽），手臂看起来从袖子里伸出来 |
| 胯部一块米黄三角 | 前腿画在躯干**之后**，大腿根的暖色轮廓线直接印在上衣下摆上 | 腿和臂全部画在躯干之前 |
| 下半身像低裆工装裤 | `crotchY = hipY + 52`，裆垂到大腿中段 | `+16` |
| 只看得见一条腿 | 前后腿色差只有 8 级明度 | 后腿 `#1A2431` / 前腿 `#2E3C4C`，且后腿的轮廓光只有 0.14 |

## 十一、里程界桩（`_drawSignposts`）

「走了多远」原本只有两处表达：顶部那条 2px 进度线、中间一行 11px 的「12.4 / 40 米」。
两处都贴在屏幕边缘，场景里看不到任何实物 —— 玩家感觉不到 40 米赛道和 3 米有什么区别。

**为什么路标不能挂在钢缆上**（试过两版，都失败）：

| 位置 | 失败方式 |
| --- | --- |
| 挂在「前方 10 米以外」的钢缆上 | 这个视角下，头顶到地平线总共只有 130px。六块牌挤在 130px 里，数字全糊成一串灰方块 |
| 挂在「前方 10 米以内」的钢缆上 | 那一段的钢丝点落在角色身体上：挑杆从脑袋里长出来、牌正好贴在耳朵边，路标和角色打对台 |

结论：**挂不上钢缆的东西，就立在它旁边。** 界桩立在云海里，横向位置严格按透视投影
（`off ∝ k`，近处贴屏幕边、远处向中线收敛）。

**2026-10-31 改为统一立在一侧**（用户要求「路标统一放一边」，原来是左右交替）：

```js
const SIGN_SIDE = -1   // -1 = 画面左，+1 = 画面右；改这一行整体翻面
```

选左侧的理由：角色右手提灯、光晕和手臂活动范围都在右侧，左侧留空给路标，
两侧不互相抢。之前「同侧 = 一排栏杆」的否决结论是在**旧的横向公式**
（`0.13 + 0.17k`，近远只差 25px）下得出的；现在横向严格 `∝ k`，同侧出来的
是一条向消失点收敛的列 —— 那正是「立在路肩上的一排桩」该有的样子。
另加两处防「斜线/栏杆」：桩位抖动 ±4%（地形本来就不绝对对齐）、
柱脚雾随近远放大（近处几根被雾埋掉大半，柱列被雾打断）。

| 约束 | 做法 | 为什么 |
| --- | --- | --- |
| 横向 | `off = min(0.32W, 0.78W * k) * jitter` | 必须 `∝ k`。写成 `0.13 + 0.17k` 时近远只差 25px，看着像平行的标签，没有纵深 |
| 侧别 | **统一 `SIGN_SIDE`（当前 = 左）**，终点桩也一样 | 交替会让人以为「左右各是一条路」；统一一侧才读成一列路肩桩 |
| 尺寸 | `s = pow(k, 0.6)` | 严格按 `k` 缩放时 30 米外的牌只有 14px 宽、字号 6px，等于没画 |
| 桩脚 | 竖向渐变到透明 + 一小团径向雾 | 硬底线的柱子是「插在云上的杆」，渐变 + 雾才读成「从云里长出来」 |
| 桩体 | 左侧暗、右侧亮两段 `fillRect` | 一整块纯色读成「一条线」，两个明暗面才是圆柱 |
| 终点 | 牌 ×1.16、金色底、双柱、`r<8` 时呼吸光晕 | 最后 8 米没有任何里程牌（下一个 10 米点就是终点），没有光晕会「目标消失」 |
| 显示范围 | `r ∈ [1.8, 34]`，且只在 `screen === 'play'` | 太近会贴边成「边框」；介绍 / 准备 / 结算页的桩会从白卡片底下露出半截竖线 |

界桩是**离屏渲染层**（`renderer.js`）的纯视觉物，不参与判定，也不读 engine 的任何计分逻辑。

### v5：换角色 —— 「提灯旅人」

**v4 的杂技演员看起来像病人。**这不是建模精度问题，是身份符号问题，三条同时成立：

| 符号 | v4 的做法 | 为什么读成患者 |
| --- | --- | --- |
| 主色 | 青绿 `#2A5F6C` | 康复科 / 护理垫 / 隔离服的颜色；而且画面是暖金逆光，冷青色的人「不在光里」 |
| 背后带子 | V 形交叉带 + 白色挂片 | 这正是**康复步态带** —— 康复科真的用它在身后扶住患者 |
| 横杆 | 腰胯高度一根白杆 | 读成助行器 / 双杠，不是杂技平衡杆 |

即便把模型做得再精细，这三样只要还在，「病人」的读法就改不掉。所以 v5 是**换一整套身份符号**：
兜帽（没有发型、没有脸、没有年龄）+ 短斗篷 + 皮靴 + 一盏提灯，全身只有双手露肤。

四处必须一起成立的设计决定：

- **主色改成暖赭**（`#6B3B2C`）。冷天空 + 亮云海 + 暖金光里，人必须是暖的才「在光里」；
  冷色只留给裤子（两条腿才数得清）和钢丝。
- **删掉平衡杆，职责交给灯**。原来那根杆的作用是让人看见「我在往哪边倒」；
  灯是画面里唯一的暖色发光体，和日出同源，不会读成医疗器械。
- **兜帽必须比斗篷深**（`#4E2A1D` < `#6B3B2C`）。第一版按「受光面朝上」给了亮一档，
  渲出来是一个被天光照亮的圆顶 —— **和一颗光头在画面上完全等价**。亮色圆顶是皮肤，
  深色圆顶才是布。
- **兜帽向一侧塌 2.2cm**。完全对称的蛋形不管刷什么颜色都是「一个几何体」；真实兜帽
  戴在头上会往一边塌，这 2cm 是「布」和「球」在剪影上的唯一差别。

删掉的部件：头球、头发壳（`haircap`）、耳朵、脖子、肩球、平衡杆、安全背带。
`eggify` / `haircap` 两个函数一并删除 —— 它们的三个坑记在下文「头发下沿」一节，
将来真要画头发再回去看。

**袖口 / 靴口这类「一圈套一圈」的结构，最大半径必须小于半腿距**（0.074）。
靴口翻边给到 0.080 时，两圈在中线处互相穿插：双腿并立时穿模藏在靴子里看不见，
一条腿抬起来，相交面就被拉成一条连接两只靴子的土色条带 —— 看起来像靴子被撕开。
收到 0.070 之后消失。

**保险绳挂点跟着改**：`BODY.hookY` 从 -133（肩胛，那里原本有背带的 D 环）挪到 -112（腰），
否则绳子会接在斗篷中段「凭空」挂住。系在腰上是登山者的常规做法，读得通。

### v4：从「锥台拼装」到「连续放样」

v3 的躯干是两个锥台（waist + chest）叠起来、腿是 4 段锥台。**段与段之间是硬接缝**，
每段各自受光，读成一节一节的塑料管；腿的半径 0.084/0.078/0.076/0.078 相邻只差
2~6mm，屏幕上就是一根等粗的柱子，没有膝盖也没有小腿肚。

这是「粗糙」的真因 —— **不是面数不够，是结构不连续**。

v4 全部改成 `loft()` 放样：一条网格从髋到肩、一条从髋到踝，半径沿高度连续变化。

| 部位 | 控制点 | 关键曲线 |
| --- | --- | --- |
| 躯干 | 13 个截面 | 下摆 0.162 → 腰 0.145 → 胸 0.180 → 肩坡 → 领口 0.090 |
| 腿 | 11 个截面 | 髋 0.084 → 膝 0.065（最细）→ 膝下 0.071 → 小腿肚 0.073 → 踝 0.049 |

手臂用 `loft_path()`（沿任意 3D 路径放样），平衡杆同样。

**着色也统一了**：v3 是「腿 flat、头 smooth」的混合着色，两套语言拼在一起最显廉价。
v4 除鞋底外全部 smooth —— 低模的「块」应该来自面数少，不是来自把每个面涂成一块。

### 背影视角的一个几何事实：球永远是一个圆

背影看到的是头在 **xz 平面上的投影**。球体在这个平面上的投影就是**一个正圆** ——
无论段数调到 40、后脑鼓包加到 6.5%、平面着色还是平滑着色，正后方看永远是「一个球」。

唯一办法是让**横向半径随高度变化**：`eggify()` 把上部略微放宽（1.02）、颅底收到 0.62。
剪影从此是「上宽下窄」，才读得出是一颗头而不是一顶帽子。
头和头发的蛋形参数必须完全一致，差几毫米头球就从一侧捅出来。

### 头发下沿 = 后颈，三个必须同时成立的约束

头发是「比头略大的椭球壳，按发际线切掉下半部分」。切法上栽了三次：

1. **`side_lift` 决定两侧的切面高度**。它等于 0 时（只按前后插值），后颈两侧各留
   一条垂到衣领的直边，中间露出一块宽约头宽的皮肤 —— 背影下就是「一张没有五官的脸」。
   给 0.30·R 之后，下沿变成「后颈中央最低、到鬓角一路上收」的倒 V。
2. **切割函数只能依赖经线角度 `phi`，不能依赖 `v.co.x`**。边界顶点要沿球面滑到
   切割线上、滑动本身就会改 x；用 x 算出来的切割线在滑动后自相矛盾 —— 函数不连续，
   边界就是一排参差的锯齿（渲出来是一圈米色小三角）。
3. **边界顶点必须沿球面滑动，不能直接把 z 改成切割线**。直接改 z 会让它脱离球面，
   和上方仍在球面上的面片穿插，同样是下沿破洞。

### 腿交叉 = 「扭曲」的真凶

大腿半径 0.084 **大于**腿距 0.074 —— 内侧故意重叠 1cm，为的是让大腿连成一片、
不出现一条从上到下的等宽竖缝（那条缝读成「两根独立柱子」）。

代价是：**只要再绕髋部拧一下（哪怕只 3°），两根轴就从「平行重叠」变成「对穿」**，
投影到 15° 偏航的画面上就是一个 X。平行重叠只读成「两腿内侧贴着」，交叉才读成「扭曲」。

内收角度现在已经归零。之前试过 8°（脚正好收到中线）和 3°，两次都交叉 ——
这是从「脚跨在两边」走向另一个更糟的极端。

### 8 帧全渲 —— 「4 帧 + 镜像」这条路走不通

试过，也上过线，最后撤了。**不是实现问题，是几何上不成立。**

`rig_anim.py` 里左右腿用 `sgn` + π 相位差严格对称、身体 `sway = sin(ph)` 也正好反号，
所以相位 π 的姿态**确实是**相位 0 关于 yz 平面的镜像。看着镜像一张图就够了。

但相机偏了 15° 偏航（为了把两条腿分开，见第十三节开头）。设相机 C(+15°)、
镜像变换 M，则真实相位 π 的画面是：

```
proj(M(P₀), C(+15°)) = M( proj(P₀, C(−15°)) )      ← 需要的是从 −15° 渲的图
而我们给的是             M( proj(P₀, C(+15°)) )      ← 从 +15° 渲的图翻过来
```

差的是一次偏航：**横向偏移 = 2·sin(15°)·y·pxPerMeter**，随物体深度 `y` 线性增长。

实测（400 宽画幅，297 px/m）：

| 部件 | 身前深度 y | 镜像前后跳变 |
| --- | --- | --- |
| 平衡杆 | ≈0.20 m | **31 px** |
| 手臂 | ≈0.15 m | 25 px |
| 躯干/头 | ≈0 | 1~2 px |

量出来的全身 bbox 中心：`184.5 → 215.5`，正好 31 px，每半个循环抖一次。
**凡是有深度的部件都躲不过这一项** —— 除非把模型压成一张纸片，而那样腿又分不开了。

现在 8 帧全渲（`FRAMES = [1,5,9,13,17,21,25,29]`，每帧 π/4），`character.js` 里
不再有任何 `scale(-1,1)`。`wire-headless-test` 的 `[8]` 里有一条断言专门守着这件事：
八帧逐格扫一遍，源矩形必须严格相邻、且**全程不允许出现负数 scale**。

代价是体积翻倍。省的办法是裁掉透明留白 + 缩一档分辨率，见下一节。

### 画幅裁切：按「身体轴」裁，不按 bbox 裁

原来的画幅是 400×600 整幅，其中 34% 是纯透明留白。裁之前先量了三样东西：

| 量的是什么 | 结果 |
| --- | --- |
| 头部中心 | 199.0 / 200.5 / 202.0 / 200.5（画幅中心 200） |
| 全身 bbox 中心 | 184.5 / 185.5 / 186.0 / 185.5 |
| 平衡杆两端 | 35 ~ 334 |

**头在正中间，bbox 却偏左 15px** —— 差的这一点全在平衡杆上。杆握在身前 20cm，
被 15° 偏航投影到左边。所以杆偏左是物理正确的，**角色真正的轴是 x=200**。

裁切框因此必须关于 x=200 对称，半宽取 `max(200−35, 334−200) + 余量 = 168`。
按 bbox 居中会把整个身体右移 15px，角色就站不到钢丝上了 —— 这种错在截图里
看起来「只是有点歪」，很难当场认出来。

竖直方向按原来那幅的 z 换算（600px / 2.02m = 297.03 px/m）：

```
顶 y=40  → z = 1.91 − 40/297.03  =  1.77533
底 y=574 → z = 1.91 − 574/297.03 = −0.02247
         ORTHO = 1.7978    CAM_Z = 0.87643    FOOT = 0.0125
```

`FOOT` 就是 `character.js` 的 `SPRITE.foot`，**两个语言各写一份**，由测试比对。

> **平衡杆在画面上偏左约 16px，这是已知现象，不是 bug。**
> 杆的横向偏移 ∝ `y·sin(偏航角)`，而「两腿在横向上分得开」也 ∝ `sin(偏航角)` ——
> 同一个几何量的一体两面。想让杆居中就必须让偏航归零，腿立刻叠成一根柱子。
> 这是二选一，不是调参能解决的。当前选择：**腿分得开**。

### 分辨率是算出来的

```
charH = min(H*0.325, W*0.62)  = 241.8 逻辑 px   ← 角色本体（1.75m）在屏幕上的高度
      × (meterH 1.7978 / 1.75) = 279.1 逻辑 px   ← 贴图显示高度（画幅覆盖 1.798m）
      × dpr 2                  = 558.2 物理像素  ← 真正的采样需求
```

所以 496 高的单帧对应 **1.13 倍拉伸**（256×384 那版是 2.8 倍，400×600 那版是 0.93 倍）。
8 帧全渲之后体积本来就翻倍，再按 1:1 采样会到 610KB，于是取了 0.929 倍 ——
312×496，实测 405.8KB（进包后）。**这一版比 4 帧的 400×600 还更清楚。**

顺带把 34% 的透明留白裁掉了（见上一节），否则这 8 帧要 550KB 以上。

**试过 256 色量化（452KB → 57KB）**：`Image.quantize` 对 RGBA 是把 alpha 当第 4 维
一起聚类，256 色撑不住「颜色 × 半透明」的组合 —— 量化后完全不通明的像素从 326k
掉到 44k，主体直接变半透明。PNG 的 `tRNS` 只给每个调色板项一个 alpha，这条路走不通。
（唯一还能试的变体是先把 alpha 二值化再量化，但边缘锯齿交给 canvas 缩放去补 —— 
收益不确定，先不动。）

### 硬约束

| 约束 | 数值 | 不这么做会怎样 |
| --- | --- | --- |
| **相机偏航** | `CAM_YAW = 15°` | 正后方 0° 时「迈步」是沿视线方向的前后位移，投影到画面上几乎为零 —— 两条腿永远叠成一根柱子，怎么调动画都读成「一条腿」 |
| **正交相机** | `ORTHO = 1.7978` / `CAM_Z = 0.87643` | 透视相机下角色随 z 有轻微缩放，循环播放时在「近头远脚」之间呼吸，一眼看出是贴图 |
| **不能镜像** | 8 帧全渲 | 偏航 15° 下镜像等于「从 −15° 看」，杆跳 31px、手臂跳 25px，每半圈抖一次 |
| **脚底锚点** | `foot = 0.0125` | 两个语言各写一份常数（`render_sprite.py` / `character.js`），改一边脚就浮在钢丝上 |
| **左右腿分色** | `pants #36485E` / `pantsLo #212D39` | 3D 里前后腿是动画决定的，没法按前后刷色；左右固定刷色视觉上等价 —— 背影下永远是「一亮一暗两条腿」，才数得出是两条 |
| **兜帽比斗篷深** | `hood #4E2A1D` < `cloak #6B3B2C` | 亮色圆顶 = 皮肤。第一版按「受光面朝上」给了亮一档，渲出来和一颗光头完全等价 |
| **兜帽不对称** | 顶尖左偏 2.2cm | 完全对称的蛋形不管刷什么颜色都是「一个几何体」；这 2cm 是「布」和「球」在剪影上的唯一差别 |
| **套圈的半径 < 半腿距** | 靴口翻边 rx ≤ 0.070 < `LEG_X 0.074` | 两圈在中线互相穿插：并立时藏在靴子里看不见，一抬腿相交面就被拉成一条连接两靴的土色条带 |
| **图集加载** | `canvas.createImage()`（不是 `wx.createImage()`） | Canvas 2D 下 `wx.createImage()` 的对象 `onload` 可能永远不触发 → `SPRITE.ready` 恒为 false → 真机永远画矢量版。**2026-10-31 真机就是这个 bug**（见下） |

### 图集怎么加载（这个坑踩过两次）

真机上角色显示成矢量版、跟图集完全不是一个东西，第一个要怀疑的就是这条路径。
`character.js` 的 `loadSprite(canvas)` 按顺序试三条，任何一条成功就停：

| 顺序 | 手段 | 说明 |
| --- | --- | --- |
| ① | `canvas.createImage()` + `img.src = '/pkgWire/assets/wire/walk8.png'` | **Canvas 2D 只认这个**。包内绝对路径以代码包根目录为基准 |
| ② | `wx.getFileSystemManager().readFileSync(...)` → `data:image/png;base64,` | 路径/分包读不到时的兜底，415KB 图约 554KB base64，只在失败时走 |
| ③ | 矢量版 | `drawWalker` 自动降级，不会白屏 |

另外还挂了一个 **2.5s 看门狗**：`onload` 有时既不触发也不报错，干等就是永远没有下文，
超时直接走 ②。加载结果写进 `SPRITE.status`（`canvas:ok` / `base64:ok` / `no-file` …），
失败时 `renderer` 会把它塞进 `app.logError('wire-sprite', …)`。

**别照抄接水果**：`pkgFruit/games/fruit/sprites.js` 至今还是 `wx.createImage()`（它的图本来就是
水果形状，退回矢量没人看得出来），而 `pkgShoot/games/shoot/sprites.js` 早就写了
「小程序里必须用 canvas.createImage()」。同一个坑，三个游戏各踩了一遍。

`wire-headless-test` 的 `[8]` 有一条断言守着「第一个尝试的必须是 `canvas.createImage()`」，
并检查加载成功后 `ready === true`、失败后 `status` 能读出原因 —— 静默退回矢量版是最难查的一类 bug。

### 建模踩过的坑

| 现象 | 真因 | 修法 |
| --- | --- | --- |
| 头顶露出一圈头皮 | 压平头发顶部（`top_flatten`）后发顶低于头球顶部 | 压平的范围会让头发最矮处低于球顶；蛋形变形已经能改轮廓，压平直接取消 |
| 后脑下方一大块皮肤 = 「一张没有五官的脸」 | 头发两侧切面太高，露出 12.6cm 的皮肤横带 | `side_lift` 0.52 → 0.30，切面落到耳上 |
| 下沿一圈锯齿 / 米色小三角 | 切割函数用 `v.co.x` 算，而滑动会改 x → 函数不连续 | 只依赖经线角度 `phi`，删除和滑动共用同一条曲线 |
| 下沿破洞、皮肤从头发里穿出 | 边界顶点直接把 z 设成切割线，脱离球面后与内表面穿插 | 保持 `phi`、解出球面点（沿经线滑动） |
| 肩上一对「肩章翘片」 | 肩头球外缘 0.209、球顶 1.434，都捅出躯干肩坡 | **不要肩球**：上臂起点埋进躯干（x 0.098），x > 躯干处自然露出来当肩头 |
| 腰胯一条浅蓝横带 = 短裙 | 胯用 `pants` 色，夹在外套下摆和腿之间是 17cm 高的亮带 | 胯改用 `jacketLo`，变成下摆内侧 |
| 腿从衣服下摆两侧鼓出来（梨形） | 大腿外缘 0.176 > 躯干底部 0.146 | 下摆给到 0.170，腿同时在 0.074/0.084 收窄 —— 衣服必须罩得住大腿根 |
| 脖子上套了个「铁圈」 | 领口 rx 0.098、脖子 0.070，中间是一圈空腔 | 脖子加粗到 0.081，领口收到 0.089 贴住 |
| 膝盖处一块方块 | 膝球横跨 Thigh/Shin 两根骨，一弯就被撕开 | **不给膝球几何**，让两端同半径，屈膝是干净折角（积木人做法） |
| 小腿和鞋断开一截 | 鞋绑 Foot、小腿绑 Shin，中间 2.5cm 真空隙 | 小腿伸进鞋里（ankle z 0.135 → 0.100） |
| 平衡杆像杠铃 | 端盖 0.029 是杆径 0.013 的两倍多 | 收到 0.016 |
| 角色在浅色云海上是个黑影 | 打光按「深色云海 + 强逆光」配的 | 大面积冷天光当主光（Fill 380 / ambient 1.55），暖逆光只留勾边，曝光 +0.35 |

### 画面上的一处连带修改：钢丝不再从头顶「长出来」

镜头在腰部高度、钢丝在脚下，所以钢丝在画面上是一条**竖线**，从脚下一直通到地平线。
角色正好站在这条线上 —— 头顶以上那一截看起来就是「头上插了根杆」。几何完全正确，
读感很糟。

`_drawWire` 的 `fadeAt(p)` 改成从 p=0.40 开始衰减、到 p=0.66（头顶）只剩 0.14。
**剪影的竖向渐变也必须共用这个函数** —— 剪影比钢缆本体宽，它才是那根「杆」的真正来源;
原来那里的停靠点是硬编码的（地平线 0.55），所以本体已经淡了、剪影还亮着。

### 失败兜底【已随图集退役】

~~`character.js` 里两条路并存：`SPRITE.ready` 走贴图，否则走矢量绘制。~~
角色已是纯矢量，**没有第二条路、没有资源加载**——不存在"加载失败"这个状态了。
`renderer.js` 不再预加载任何东西。图集时代的教训保留在上面，接水果

换贴图时用得上。

## 十四、Q 版提灯旅人（v6，2026-10-31，已被 v7 取代）

> **⚠️ 本章是上一版。** 用户对 v6 的评价是「还是怪怪的」——放大特写核对后确认：
> 不是画得糙，是**风格割裂**（角色是高饱和扁平贴纸，背景是低饱和空气感云海）
> + **光源不统一**（灯在发光却没照亮任何东西）+ **兜帽还是纯色蛋**。
> 现役是第十五章的「绘本风旅人 v7」。本章保留是因为它记录了从 3D 退回矢量的
> 决策过程（那部分仍然成立）。

用户对 v5 的评价是「还是好丑，没有吸引力」。诊断不是配色问题，是三个**结构性**缺陷：

| 缺陷 | 表现 | 为什么救不了 |
| --- | --- | --- |
| 兜帽 = 纯色蛋 | 占全身 1/3 高的光滑椭圆，背面视角下帽尖/翻边全都没显出来 | 放样能控制轮廓，控制不了"魅力" |
| 躯干 = 直筒圆罐 | 没腰、没肩坡，披肩被曲面切成一块矩形补丁 | 修一版要重跑整条 Blender 管线 |
| 剪影无节奏 | 蛋 + 罐 + 两根牙签，没有宽-窄-宽呼吸感 | 低模平滑着色的脸熟就是橡皮泥 |

**解法 = Q 版 2.5 头身 + 纯矢量实时绘制**。大圆头自带萌感是设计出来的，
不是渲出来的；每个像素可控；改一版重编译就能看；动画从 8 帧离散变连续相位；
顺带删掉 409KB 图集和整条加载故障链。

### 设计要点（`character.js`）

| 要点 | 数值/做法 | 原因 |
| --- | --- | --- |
| 头身比 | 头 r=41（直径 82 = 全身 43%），总高仍 190px | Q 版的骨架；`charScale = charH/190` 不用动 |
| 头底盖肩线 | `headCY+headR = -106`，肩披顶 -111 | Q 版没有脖子，头直接坐在肩披上 |
| 兜帽垂尖 | 左上一撮布尖（非对称） | 对称圆 = 几何体；这撮尖是"布"和"球"的全部差别（v5 的 2.2cm 结论的 2D 版） |
| 兜帽比斗篷深 | `#5A3226` < `#A95537` | 亮圆顶 = 光头，深圆顶 = 布（v5 硬约束延续，有测试） |
| 剪影节奏 | 大圆头(宽) → 收肩(窄) → A 形下摆(宽) | 可爱的骨架，测试卡 0.38~0.50 头身比 |
| 提灯 | 挂在斗篷轮廓**外**，压一条内缘；钟摆式滞后摆动 | 全在轮廓外 = 灯浮着；全在里面 = 看不见 |
| 提灯公式同源 | 臂 `sin(phase-0.7)` / 灯 `sin(phase-0.9)` | 灯比手滞后一点才有钟摆感，但两处公式必须一起改，否则"脱手" |
| 腿 | 只露 34px，靴比腿宽、有翻边 | 腿短 + 靴大是 Q 版的全部秘密 |

### 走路四条硬规则不变，但换成 `gait()` 纯函数

`gait(phase, speed, balance)` 返回全部步态量，`wire-headless-test [8]` 逐 72 相位扫描：

- **规则 a**：`liftR × liftL === 0`（两腿相位差 π，任何时刻至少一腳在钢丝）；
- **规则 c**：`bob ≤ 0` 恒成立、双腿并拢时身体最高（`|cos|` 两倍步频）；
- 重心转移：抬脚时 `swayX` 指向对侧；
- 8 相位全程无负 `scale`（防"4 帧 + 镜像"复活）；
- **静态扫描**：`character.js` 里不得再出现 `SPRITE` / `createImage` / `drawImage`，
  `walk8.png` 不得回到包里——图集链路**禁止复活**。

### 真机部署

无任何异步资源，编译即所见。之前"人物不是图集的样子"那类问题在架构上不可能再出现。

## 十五、绘本风旅人 v7 —— 现役角色（2026-10-31）

v6 之后用户要求「适配我的背景，再换一个角色，精致一点」。这一版是**逐条讨论后
定的**（风格 → 形象 → 画面重量 → 载体），不是拍脑袋改配色。

### 三条决定

| 分支 | 选择 | 为什么不选别的 |
| --- | --- | --- |
| 风格 | **A 绘本插画风**（4.5 头身、低饱和、布料层次） | B 逆光剪影：小尺寸（约 240px）下腿部动作会糊成一团，训练反馈变弱；C 半写实 6.5 头身：**成人比例 + 细致服饰在康复语境里容易又读成"患者"**（v4 被否的同一条路） |
| 形象 | **露发 + 长飘带围巾** | 兜帽是纯色蛋的根源，必须去掉；飘带是唯一能表现**风/速度/失衡**的元素（康复训练要即时反馈），且没有任何医疗符号 |
| 画面重量 | **中低调 + 统一光源** | 角色压到中暗，暗部用云海的冷灰蓝；亮部与边缘光交给远处的太阳，提灯只作第二光源照亮身侧。视觉主角交给钢丝与地平线 |
| 载体 | 纯矢量（不提问，直接定） | 图集链路刚整条删掉；绘本风的"精致"靠分层绘制，矢量完全能做到，且零加载、随 dpr 锐利、包体不变 |

### 设计要点（`character.js`，总高仍 190px）

| 要点 | 数值 / 做法 | 原因 |
| --- | --- | --- |
| 4.5 头身 | 头 r=19（直径 38 = 全身 20%），颈 -151~-146 | 头身比有测试卡 0.17~0.24 |
| 露发 | 后脑大形 + 三条发丝 + 鬓角 + 低马尾发圈 + **顶部柔光（不是描弧）** | 兜帽 = 纯色蛋；描弧 = 帽檐（试过两次都读成帽檐） |
| 飞发 | **整条删除** | 深色头发上任何细而亮的线都读成"虫须"（试过两版，元素错了不是参数问题） |
| 飘带 | spine 是 C 形弧（**静止时也要有弧**）+ 分段递减 lineWidth（8.6→5.0→2.4）| 直线 = 硬邦邦的触角；等宽 = 塑料布条 |
| 飘带对比度 | `scarf #B96A4E` vs `coat #7E5443` | 第一版两色几乎一样，飘带整条淹没在大衣里，"飘带不见了"的真因是对比度不是长度 |
| 大衣 | A 形 + 翻领 + 背缝 + 两道褶 + 下摆内侧暗 + 云海反光边 + 提灯暖光（clip 在衣摆上） | 精致感来自层次；灯不照亮衣服 = 黄色贴纸 |
| 手臂 | 近侧 `coatShade`、远侧 `coatShadow`，都与大衣不同色 | 同色手臂会和大衣糊成一片 |
| 提灯 | 尺寸比 v6 小、光晕更收、挂在轮廓**外**（手 +13） | 中低调下不该抢戏；压在衣摆上就分不出来 |

### 康复语境红线（改任何部分都不能破）

不能有**杖**（读成助行器）、不能有**背带/胸带**（= 康复步态带，所以飘带必须画在身体**之后**）、
主色不能用青绿、不能画脸/读表情、不能有失败羞耻。

### 测试守护（`wire-headless-test [8]`）

零图集（静态扫描禁 `SPRITE`/`createImage`/`drawImage`）、**禁止兜帽复活**（PALETTE 不得有 `hood`）、
头发比大衣深、飘带必须画在身体之后（源码里 `drawStreamers` 要排在 `drawCoat` 之前）、
4.5~5.5 头身区间、步态四规则逐 72 相位扫描、8 相位无负 scale。

### v7.1：去恐怖（2026-10-31，用户反馈"角色一点恐怖"）

**恐怖感的配方是三样东西同时成立**：背影（看不到脸）+ 一整块近黑头发盖满后脑
（`hair #4A3B36`）+ 颈后垂下一束（低马尾）。这三样凑齐就是恐怖片里
"无脸黑发背影"的标准写法。上一版有兜帽时读成"衣服"，去掉兜帽换成深色头发后
恐怖感立刻出现 —— 所以**去兜帽这件事必须配套去恐怖**，不能只换发型。

| 改动 | 做法 | 原因 |
| --- | --- | --- |
| 发色 | `#4A3B36` → 暖栗棕 `#6B4A38`（大衣同步提亮半档以守住"头发比大衣深"） | 近黑 + 无脸 = 阴森；暖栗棕 = 人 |
| 后颈 | **露出 5px 皮肤**（上一版是深色），并加头发压在颈上的一道投影 | 一坨没有皮肤的头 = "不是人"。v5 那条"不能露脖子"只在**有兜帽**时成立 |
| 低马尾 | **整束删除**，改成两侧外翘的短发尾 | 颈后垂一束 = "头发后面藏着什么"，是恐怖感最直接的来源 |
| 头部暗面 | alpha 0.55 → 0.32 | 没有脸的前提下，任何大面积阴影都会读成"藏在暗处的东西" |
| 发夹 | 右侧一小块亮色 `#D8A870` | "这个人在打理自己"的最便宜信号，也把暖色带到头部 |

连带微调：飘带末端收在腰线（垂到衣摆会被当成第三条手臂）、主线宽 8.6 → 8.0。

### v7.2：第二轮去恐怖（用户第二次说"有一点恐怖"）

第一轮改完之后仍然恐怖，于是做了**逐部位排查**，结论：恐怖不是一处，是
"没有脸"的前提下，**任何一块浅色/亮色小色块都会被大脑补成一个器官**。

| 排查到的部位 | 被读成什么 | 修法 |
| --- | --- | --- |
| **后颈露出的肤色块**（第一轮我为了"证明这是个人"加的） | 头下、深色躯干上的小块浅色 = **一张苍白的小脸 / 绷带** | **撤回**：颈根由围巾 + 立领包住，只留暗影。人的证据改由"暖栗发色 + 发夹 + 有轮廓的发型"承担 |
| **围巾在头两侧露出的两个橙色方块** | 又一处"小脸" | 围巾两端 ±13 → ±9.5，下缘暗面加粗到 4.2，头外只留窄窄一条 |
| **发夹放在侧脸中央 (0.50r, +0.06r)** | 一块亮色横条 = **半睁的眼睛** | 移到耳后下方 (0.72r, +0.52r)：那里是发尾，亮色读作装饰不是器官 |
| **飘带起点在颈后** | 头的两侧下方各一条橙色 = **耳朵 / 触角** | 起点下移到肩后（藏进大衣），飘带从腰线才露出来 |
| 手（4px 暗色圆点）在细手臂末端 | 枯爪 | 加大到 ~5 并加暖色亮边 |
| 头部是**正圆** | 无五官的完美圆形 = 空白的脸 | `hairPath()` 替代 arc：顶部略平、两侧不对称、下发尾内收；再加一撮**粗而短**的呆毛（注意区别于被删掉的"细而亮"的飞发） |
| 整体偏暗 + 手臂细长下垂 | 黑暗中的提灯人影 | 发色/大衣再提亮半档、手臂加粗并抬高、提灯洒在衣摆上的暖光加强 |

**这条经验值得单独记住**：在没有脸的角色上，浅色小色块的位置就是"器官的位置"——
放中间是眼睛，放头下是小脸，放头两侧是耳朵。要么不放，要么放到明确是
衣饰/发饰的地方。

## 十六、场景特效 fx.js（2026-11-01）

三件特效集中在 `games/wire/fx.js`（纯函数、无状态、零图片），方法借自
pixelfx 库（剧本 + 调色 ramp + easeOut 手感 + 确定性），**但不借它的像素** ——
它的成品是低分辨率硬边像素风，放进绘本风晨光场景就是贴纸；绘制仍走矢量
Canvas 原生分辨率。

| 特效 | 触发 | 剧本 | 关键决定 |
| --- | --- | --- | --- |
| `drawMotes` 氛围浮尘 | 常驻（所有界面） | 13 粒暖金光尘悬在云海与钢丝之间，缓慢上浮（近快远慢的视差）、水平轻漂、各自周期呼吸；回绕端 34px 淡出 | 与 `depth.drawDust` 的白尘分工：那层是「空气」（细密纯白），这层是「晨光」（稀疏光晕）。约 1/5 是冷色（天光反光），全暖会腻 |
| `drawWind` 失衡风线 | `warnGlow > 0.03`（play） | 3 条冷蓝风线从 lean 侧掠过，头部快尾细带卷，随行 5 粒碎光；行程两端淡入淡出 | **颜色是冷钢蓝不是白** —— 云海是亮的，近白会被洗没（第一版踩过）。康复红线：失衡是「风大了」，风线绝不用红/橙（那是渐晕的事）；与角色飘带同源（都跟 lean） |
| `drawGoldDust` 过桩金尘 | `showMilestone`（play） | 脚下升起 18 粒琥珀金光尘，easeOutCubic 外散 + easeOutQuart 上飘，收细淡出，1.4s 归零；原点一圈柔光同步扩散 | 与「已走过 N 米」飘字同帧：字说结论，金尘说情绪。亮云背景上淡金会被洗成白点 —— 主体必须用饱和琥珀（#F4A848），浅金只留给热核 |

### 铁规矩（`wire-headless-test [9]` 守着，18 项）

- **确定性契约**：所有粒子是 `(t, 序号)` 的纯函数 —— 内部只用固定种子 hash
  （sin 大数取小数），**不出现 Math.random、不持有可变状态**。同 t 画两次
  逐调用一致（射击游戏踩过同帧重绘不一致的坑）。
- **零开销门槛**：`warn=0` 时 `drawWind` 直接 return，不产生任何绘制调用。
- **结束于空**：金尘 1.4s 后完全归零，不残留。
- **红线扫描**：风线源码段不得出现红/橙警示色；不得加载图片。

预览演示参数：`?mile=20`（钉住飘字+金尘）、`?warn=0.9`（强制风线强度）。

## 十七、小狐狸角色（AI 生成 sprite，2026-11-01）

用户侧接入 AI 生成的绘本风小狐狸（5 帧走路循环 sprite），`renderer.js` 改引
`character-fox.js`（254KB，base64 内嵌）；矢量旅人 `character.js` 保留为留档。

### 真机「角色不显示、只剩一个橙色圆点」（第四次才定位到真因）

前三次的判断**全部是错的**。依次以为是：data URI 太大 → 分包路径不行 → 主包路径不行。
每次都在改路径和编码方式，真机永远还是橙点，因为真正的原因是**根本拿不到 Canvas**。

微信小程序的 `CanvasRenderingContext2D` **没有 `ctx.canvas` 属性**——那是浏览器
W3C 规范的属性，小程序没实现。`character-fox.js` 里写的是

```js
function foxMakeImage(canvas) { ... }
ensureFox(ctx && ctx.canvas)          // ← 真机上永远是 undefined
```

于是 `canvas.createImage()` 一次都没被调用过，一路退回 `wx.createImage()`。而
`wx.createImage()` 造出来的 Image 对象**不仅 onload 不触发，也不能交给 canvas 2d
的 `drawImage`**——它和 canvas 不在同一条渲染管线里。

浏览器预览为什么一直正常？因为浏览器的 ctx 标准属性里**有** `canvas`。所以本地
永远复现不了，只有真机挂。这解释了整整一天「工具里好好的、真机只剩橙点」。

**修法**：renderer 把 canvas 显式交给角色模块，不再靠 ctx 反推。

```js
drawWalker(ctx, { canvas: this.canvas, x: ..., y: ... })
```

`character-fox.js` 只认 `o.canvas.createImage()`；真机上如果拿不到 canvas，直接报
`nocv` 并画兜底圆点，**绝不**退到 `wx.createImage`（它只在 `IS_WEB` 分支里留给
浏览器预览的 stub 用，stub 负责把 `/assets/…` 重写成 `../../assets/…`）。

### 加载档位与状态机

| 档 | 做法 | 说明 |
|---|---|---|
| 0 | `wx.getImageInfo('assets/wire/fox-walk-190.png')` → `wxfile://` 临时路径 → `img.src` | 相对路径写法，官方描述的就是「相对路径」 |
| 1 | `img.src = '/assets/wire/fox-walk-190.png'` | 绝对路径直连，包内路径官方支持 |

**旧状态机有个隐藏死循环**：`img.onerror` 只把 `foxTried` 置 false，下一帧进入
`ensureFox` 时走不到升档分支，于是在同一档位无限重试，档位永远停在原地。现在
失败时**主动升档并保持冷却**（`foxStage = 1`），2.6s 后重试。

真机上兜底圆点下方会画一行 `fox:<note>`：`info`（正在换临时路径）/ `tmp`（已拿到
临时路径，等 onload）/ `ok0`、`ok1`（成功档位）/ `file` / `err1` / `nocv`（没拿到
canvas）/ `noCIM`（canvas 没有 createImage）。这行字只在真机画，预览和 headless
都不画——否则两帧渲染结果不一致，`[9]` 的确定性契约会红。


### sprite 内容偏移（判定中心红线）

pngjs 实测五帧 alpha 质心 x = 76.6~77.3，而帧中心是 66 —— **AI 生成的狐狸整体
偏右约 11px**。绘制以帧中心对齐钢丝，不补偿就站在钢丝右侧。`drawWalker` 里
`CX_FIX = 11`（sprite 坐标）向左补。垂直方向脚底 189≈帧底，贴地正确不用补。

### 帧索引 bug

`Math.floor(phase) % 5` 把 2π 弧度拆成 6 份（帧序 0,1,2,3,4,0,1），已改为按弧度
比例映射：`floor(cyc/2π*5) % 5`。

### 体积

250KB 内联 base64 已删（它在这条链路上从来没成功过一次，只是把 JS 撑到 257KB）。
`character-fox.js` 257KB → 7.1KB，全包 3062.9 → **2820.7 KB**，主包 1120.0 KB。
sprite 本体 `assets/wire/fox-walk-190.png` 189KB 在主包（`pack-size-check` 里是
进包最大文件，仍远低于 2MB 红线）。

### 测试守护（`wire-headless-test [10]`，11 项）

禁 data URI / JS 体积 < 30KB / `o.canvas` 优先于 `ctx.canvas` / `wx.createImage`
只在 `IS_WEB` 分支 / **renderer 调 drawWalker 必须传 canvas** / 传了就真的 ready /
优先走 getImageInfo / 绝不落到 wx.createImage / 缺 canvas 报 nocv / 缺 canvas 也不
碰 wx.createImage / getImageInfo 失败能升到档 1。

其中「传了就真的 ready」是**运行时**断言：用一双微信语义的假 canvas（ctx 上没有
canvas 属性）跑一遍，只有真的从 `o.canvas` 拿到 Canvas 实例才能通过。

## 十八、失衡不再自动回正 + 提速 + 三个角色（2026-11-01）

用户原话：

> 走钢丝界面要失去平衡不要自动用保险绳回正要引导患者回正，给音效和特效，
> 游戏感觉整体速度好慢，加快速度和距离，然后再设计小兔子和小熊猫的角色
> 加上我现在的小狐狸就是 3 个角色。

### 18.1 「自动回正」到底做了什么

`safety.js` 的 `getSuppression()` 在绳索介入时把控制量乘 `(1 - ropePull × 张力)`，
第 2 档 `ropePull = 0.6` —— 患者身体偏到 1.0，游戏只按 0.4 算。
再叠加 `engine.js` 里 `balance = max(balance, 0.22)` 的托底和 `speedFactor *= 0.5`，
结果是**失衡既不疼也不危险，只是变慢**。

这是康复训练里最不该做的：患者学不到「自己把重心找回来」这件事本身，
他学到的是「歪了也没关系，游戏会兜住」。

### 18.2 现在绳索只做三件事

1. 判断等级（正常 / 失衡 / 越界）；
2. 给出**引导方向**（该往哪边压回去）；
3. 记录次数与时长（治疗师指标）。

**它不再碰控制量。** `effNx = nx`、`effNy = ny` 原样进入平衡模型。
`getSuppression()` 这个方法已经整个删掉，测试 `[3b]` 守着它不许复活。

### 18.3 平衡值 = 速度系数

```js
speedFactor = balance          // 站得稳全速、晃就慢、掉到 0 就停住
if (safety.engaged) speedFactor *= 0.12   // 越界几乎停住
```

旧公式是 `0.35 + 0.65 * balance`（**下限 35%**），意味着患者怎么晃都还能走。
现在跌到 0 就真的停住，唯一的出路是**患者自己把重心找回来**
（回到 `effLoad ≤ 0.18` 后按 `recoveryRate` 回升）。

越界保留 12% 而不是 0：完全 0 会让画面看着像卡死，12% 配合绳索绷紧的姿态，
读起来是「在硬撑」而不是「死机」。

### 18.4 引导：三道同向的信号

| 信号 | 位置 | 作用 |
|---|---|---|
| 角色倾斜 | 身体 | `lean = effNx * 0.34`，去掉抑制后自然更明显 |
| 引导箭头 | **屏幕上方的 HUD 区** | `fx.drawGuideArrow()`：66% 屏宽的大箭头，指向该压的方向（2026-11-01 从腰部光带改成这个，理由见 18.11） |
| 屏幕余光 | 画面该侧边缘 | 冷白柔光，越失衡越亮 |

另有 **失衡音效**（`wire_wobble`：两个相差 12Hz 的低频产生慢拍频 = 「晃」）
和 **越界音效**（`wire_edge`：低频下坠 + 摩擦噪声），
文字提示直接给方向（「往左压一点」）。回正成功复用 `combo`（上行双音）。

**左右才有光带，前后只给文字。** 前后失衡（往前栽/往后仰）用横向光带画出来
只能横着指，读着是错的；竖着画又会和钢丝、绳索抢同一条轴线。
前后失衡在康复里的处置本来就是口令，所以只出文字。

### 18.5 顺手修掉的一条康复红线

原来失衡时**两侧边缘一起泛红**（`rgba(226,85,60)`）。两个问题：
红色 + 双侧同时亮 = 「你错了」，而失衡要表达的是「现在往这边压」；
双侧同时亮还等于没有方向。现在只在**该去的那一侧**亮冷白柔光。

### 18.6 提速与里程

| | 改前 | 改后 |
|---|---|---|
| 第 2 档 | 90 秒 / 40 米 / 0.5 m/s | 90 秒 / 100 米 / 1.2 m/s |
| 第 5 档 | 60 秒 / 55 米 / 0.82 m/s | 60 秒 / 95 米 / 1.8 m/s |

0.44 m/s 在临床上属于**慢速步态**（普通人 1.2~1.4 m/s），所以「慢」是客观的。

**关键取舍：患者并不真的走路**，只做重心转移，角色替他在钢丝上前进。
所以调快 `forwardSpeed` 只影响画面节奏和里程数字，**不会要求患者动得更快**。
这一点必须写进配置说明，否则治疗师会以为「调快 = 加难度」。

连带改动：
- `scorePerMeter` 4 → 1.5（里程翻 2.5 倍，分数不该跟着翻）
- 界桩与里程碑间距随里程自适应（`_mileStep()`：≤60 米每 10 米，更长每 20 米）。
  否则 100 米会立 10 根桩、报 10 次里程碑，语音变吵、桩连成一排。
- `walkPhase += step * (2.1 + speed * 3.4)`：速度提上来之后步频自动变快
  （0.6 步/秒 → 1.3 步/秒），这一步不用改，是提速的附赠收益。
- 结算新增 `rulesVersion: 'v2'` 与 `avgSpeed`。**v1 与 v2 的里程、速度、分数不可比。**

### 18.7 三个角色

`character-fox.js` 泛化成 `character-sprite.js`，三只共用同一套 5 帧背影走路循环：

| id | 名字 | 图集 | 帧宽 |
|---|---|---|---|
| fox | 小狐狸 | `assets/wire/fox-walk-190.png` | 132 |
| rabbit | 小兔子 | `assets/wire/char-rabbit.png` | 88 |
| panda | 小熊猫 | `assets/wire/char-panda.png` | 110 |

**纯外观，不影响手感。** 治疗师要拿同一档位做前后对比，角色如果带属性
（比如熊猫更稳），换角色就等于换难度，前后对比就废了。

入口在介绍页：标题下面三枚胶囊，点一下画面里的小人当场换掉 —— 比开面板确认直观。

### 18.8 sprite 处理的四个坑（`tools/process-wire-sprite.js`）

| 坑 | 现象 | 正解 |
|---|---|---|
| 按 W/5 硬切 | 五帧边界随机切进耳朵或尾巴 | **按列空隙切**：扫每列有无内容，连续空 6 列才算分界 |
| 逐帧缩放到等高 | 抬腿的那一帧被拉高，走路像在呼吸 | 五帧**共用同一个缩放比**，按最高帧定标 |
| 色键抠白底 | 水彩纸颗粒也是近白 → 角色身上挖出成片小洞（深色背景一眼看出青粉麻点） | **从四边泛洪**，只有连到画外的白像素才算背景；轮廓内的白高光保留 |
| 最近邻降采样 | 柔边抽成台阶，还随机把纯白背景像素抽进来 = 白毛边 | **箱式面积平均** + alpha 预乘 |

还有一条纯粹是我自己写出来的 bug，值得单说：

> 量化到 5bit 时 `Math.round(252/8)*8 = 256`，直接写进 `Buffer` **溢出成 0**。
> 于是所有接近纯白的像素 R 变 0、G/B 还是 248 —— 白毛边变成一圈**青色麻点**。
> 我一开始以为是色键没抠干净，白改了三条路线。**写 Buffer 一律先 clamp。**

量化本身是必要的：水彩渐变压不动，三张图 528KB 会把主包顶到 72%。
5bit RGB + 4 档 alpha 后 528 → 315KB，而角色在屏幕上只有 105×140 逻辑像素，
肉眼分辨不出色阶。

### 18.9 又一个只在真机/慢网络出现的 bug

`setCharacter()` 一开始写成：

```js
if (next === ST.id && ST.ready) return   // 没 ready 就往下走 → reset()
```

renderer 每帧都调它，于是**加载途中的 Image 下一帧就被清掉、重新开始**，
图片永远加载不出来。表现是「三只里随机一只只剩兜底圆点」，
而且在我的截图里时好时坏（浏览器缓存命中时刚好能成）。
现在只在 **id 真的变了** 才 reset，测试补了一条「加载途中重复设置不打断加载」。

### 18.10 两个「代码全对、屏幕上就是不对」的坑

**① 改出厂参数对老设备完全无效**

把前进速度从 0.5 提到 1.2、里程从 40 提到 100，用户屏幕上仍然写着
「里程 1.5 / **40 米**」，一秒走 0.5 米 —— 一行代码都没错，那个 40 是**上一版存在
storage 里的**。

`config-store.load()` 是「盘上有就以盘上为准」，改 `SCHEMA` 的 `def`、改 `PRESETS`
都只对新装的设备生效。而配置是**治疗师所有**的，不能简单清盘（会冲掉他手调的参数
和标定）。

现在加了规则集迁移（`utils/wire-config.js`）：

```js
RULESET_V2 = {
  forwardSpeed:  { 0.4:1.05, 0.5:1.2, 0.62:1.4, 0.72:1.6, 0.82:1.8 },
  trackLength:   { 30:110, 40:100, 45:100, 50:100, 55:95 },
  scorePerMeter: { 4:1.5 }
}
```

只迁**出厂值**。治疗师手调过的数字（0.75、65 米）不在表里，一个都不动 ——
宁可漏迁，也不能把个体化参数冲掉。迁完写 `wire_ruleset = 2`，下次不再迁。
测试 `[11]` 用一份「上一版的盘」端到端验证这两件事。

> **规则：以后凡是改「出厂值 / 预设」，必须同时升 `RULESET_VERSION` 并补映射。**
> 否则等于没改 —— 只有新装的设备会变。

**② 箭头尖端画在了近端**

```js
moveTo(ax-off+8, ay-8) → lineTo(ax-off-2, ay) → lineTo(ax-off+8, ay+8)
```

顶点在 `-2`，两臂在 `+8`，人字形是**朝身体张开**的。再套上 `dir<0` 的镜像，
两边都变成「箭头指回角色自己」—— 截图里就是「往左压」配着一个 `⇒`。

修法：尖端 = 最外侧那个点（`tipX = ax + REACH`），两臂往后张开。
`[12]` 直接读 ctx 的路径点断言「尖端 x 大于两臂 x」，不靠人眼看图。

### 18.11 引导从腰部搬到屏幕上方的 HUD 区

用户原话：**「把引导放在屏幕上部分，大一点。」**

改之前是「从角色腰部朝该压的方向长出一道 60~90px 的光带」。问题不是审美：

1. 它夹在云海纹理、角色、钢丝之间，**底色本身就在变化** —— 光带一半压在云脊上
   一半压在雾里，看上去像一根斜着的标尺，读不出「往哪边」；
2. 失衡时人第一反应是看**画面中央偏上**（所有游戏 HUD 的固定位置）。
   把方向放在那儿，不需要教；放在腰上，需要教一次。

现在是 `fx.drawGuideArrow()`：一枚 66% 屏宽（上限 300）的大箭头，挂在
「HUD 主行 + 状态行」下方、地平线以上，水平居中，尖端朝该压的方向。

实现上的四条约束：

| 约束 | 原因 |
|---|---|
| **尾端圆角、尖端必须尖** | 直角尾 + 尖头的组合像贴纸；圆尾 + 尖头才像指示牌。圆头箭头在任何尺寸下都读不出「往这边」 |
| 三层：外发光 → 深色填充 → 冷白描边 | 亮云海/暖地平线上靠深色填充读形，深色天空上靠亮描边读边。单靠 alpha 叠光会被洗没（踩过三次） |
| **只做亮度呼吸，不做位移** | 视线中心的大箭头一滑就分心 |
| `cy` 夹在「HUD 下沿 +30」和「地平线 −10 − 高度」之间 | 320×568 上地平线只有 190px 高，按固定偏移会压到远山剪影上，实心部分就没有对比了 |

**测试 `[13]` 直接读渲染参数**（把 `fx.drawGuideArrow` 换成探针）：站得稳时一次都不调、
越界时 `cy < H/2`、`cy > 100`、`len ≥ 0.45W`、方向朝该压的一侧、水平居中。
`[12]` 读 ctx 路径点，断言「尖端就是最外点」「尾部光痕在箭尾之外」。

### 18.12 预览工具的 `freeze` 参数以前根本没生效

截图里角色时有时无，我一度以为是加载 bug。真相是：`tools/wire-preview/main.js`
**从来没有读过 `freeze`**，循环一直按真实时间推进，图集还没解码完就截图了。

现在 `?freeze=1` 只冻结**状态**（不再 `engine.update`、`render(dt=0)`），
**不冻结绘制** —— 图集一就位画面就补上。真机上循环一直跑，所以这个 bug
只在「截图核对」时出现，属于工具问题、不是产品问题，但它骗了我两次。

### 18.13 界面体检（impeccable + design-taste 审查后落的六件事）

用户原话：「分析我走钢丝的界面，看看有没有要改的，个人感觉箭头有点大。」

实测数据先摆出来（390 宽屏）：箭头 257×69，角色 140×110，**箭头面积 ≈ 角色 43%**，
而且画在日出辉光带上方 —— 全画面对比最强的一块深色。视线先落箭头、角色第二，
对体感训练来说主次反了：患者该看的是身体，箭头只是提示。

| # | 改动 | 关键判断 |
|---|---|---|
| 1 | 箭头**变细变长再压暗**：头高 0.27→0.19、杆 0.085→0.042、长 0.66W→0.70W，填充 alpha 0.72→0.42，删外发光描边和尾部两道光痕 | 缩小还是「小黑板」，变细才像指示牌；外发光让它看起来比实际大一圈，正是「箭头有点大」的直接来源；光痕在细箭头下读成第二个箭头 |
| 2 | 开始 / 准备 / 结算三页白卡 → **暗玻璃**（`C.ink` 整套翻转为暖白，新增 `C.onLight`） | 游戏内一个容器都没有、游戏外全是白卡 = 两套皮肤；深字色必须整套翻转，只改卡底会白底白字 |
| 3 | 结算页：评级环（读成加载圈、弧长是编的）→ **大字母**；删掉与文字行重复的四统计块 | 「用图形代替内容」是典型的假设计 |
| 4 | 准备页：卡片叠在副标题与按钮间**竖直居中**（原来下方空 300px）；零点行加玻璃条；「关闭模拟」上移不再压副标题 | 一大块空白读起来像「没做完」；琥珀小字直接压亮云等于没写 |
| 5 | 平衡条：加**中线**（轨道上方短竖线）、安全区薄荷绿→暖白、点的颜色 青→冷白/琥珀/暖橙三档 | 没有中线「离站直还差多少」只能猜；薄荷绿是整屏唯一绿色，读成进度条 |
| 6 | HUD 标签 9px → 11px，静音色 0.50 → 0.62 | 9px 是「设计稿看得见、老人机看不见」的尺寸 |

**修复的一个真 bug**：`character-sprite.js` 里加载用的 `Image` 是函数局部变量，
函数返回后没有任何引用持有它 —— **加载完成前被 GC，onload 永远不触发**。
表现是截图里「角色时有时无」（实测连截三次 1 次missing）。现在 `ST.pending` 持有
引用直到 load/error 结束。预览工具同时把三张图集在开循环前预热 + `decode()`。
